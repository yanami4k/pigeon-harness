# 子 agent 与会话的统一改造 · ⑦：会话面板里的 Ctrl+X 与等审批标记（基线 b06cb1f）

457 不分段，接着做剩下的四项；本块是其中两项：面板里 Ctrl+X 的两下语义、使用者不在某个会话时它（含它的子 agent）等审批的标记。细化记为决策 483。

## 一、改动

| 文件 | 内容 |
| --- | --- |
| `src/application/session-pool.ts` | `stop` 改为只停这一轮：在跑的中断，运行面不释放，记为人停下的（不被后台作业、子 agent 交回的结果叫醒）；新增 `remove`：从面板去掉并释放运行面（面板会话的 `close` 里注销通讯录，它派出的子 agent 一并停下），还在开的开完即释放；`send` 给停下的会话即接着干（停着期间排着的通知随这一轮一并交给它）；`take` 对停下的会话按还开着取；关掉 Pigeon 时逐个释放；卡片的"等待回应"在停下的会话里也标，答完回到已停（没停的答完按在不在跑回到在跑或空闲，原来一律回到在跑） |
| `src/tui/shell.ts` | 面板里别的会话的 Ctrl+X：第一下停下（不再先提示），两秒内再按一下从面板去掉；已停下的第一下只等第二下。当前会话那张卡照 458（连按两下中断这一轮），间隔同为两秒。当前会话那张卡在它的子 agent 等审批时标等待回应 |
| 测试 | `session-pool.test.ts`、`main-pool.test.ts`、`session-panel.test.ts` 改写按旧语义（停下即释放）的断言；新增：停下的会话不被叫醒、收到话即接着干、去掉才释放；停下的会话里子 agent 等审批照样标出；当前会话那张卡因子 agent 等审批标出 |
| 文档 | `docs/configuration.md` 会话面板一节与键位表、子 agent 一节；决策 483 与索引行；443 标部分已改 |

## 二、工程上的取舍

- 停下的会话照样可以 `/take`，按还开着取（起点前移、工作树留着）；工作树的清理挪到从面板去掉时（没有改动即删，有改动保留），原来是"已停的会话完整取回即删工作树"。会话还能接着干，删了工作树就接不上。
- 当前会话那张卡连按两下的间隔由 1.5 秒改为 2 秒，与别的会话"两秒内再按一下"一致。
- 停下的会话第一下 Ctrl+X 不出提示，只等第二下（照"界面不加提醒"）；当前会话那张卡原有的"再按一次即中断"提示保留（458 的做法）。
- "去掉"只去掉本进程面板上这一行；跨工作区的工作清单（用户级索引）在⑨里接上，届时去掉同时删出索引。

## 四、独立审查与修正

审查对照 b06cb1f 看了提交的改动，另写了几个场景测试复现。发现与处理如下。

| 发现 | 处理 |
| --- | --- |
| `/resume` 与会话选择器只排除没停的面板会话；停下的会话运行面还开着，续接过去即两个运行面写同一个会话文件 | 面板里的会话（含停下的）一律排除；文档改为"先从面板去掉" |
| 开运行面期间被停的会话运行面已释放，`send` 仍能让它"接着干"（在已关掉的运行面上跑钩子与这一轮），`take` 仍按开着取 | 已释放的会话 `send`、`take` 都答 `session <名字> is stopped` |
| 拿运行面的 `isRunning` 判断这一轮在不在跑：UserPromptSubmit 钩子、开跑前的压缩等窗口里它为假，于是停下时不中断、第二次发话会再开一轮 | 会话池自己记着在途的这一轮（从发出到落定），`send`、`take`、叫醒都看它；停下时一律中断；等 UserPromptSubmit 钩子期间被停下的这一轮不开跑 |
| 等审批标记在几条路径上丢：这一轮跑完时清掉、几条一起挂着时答了一条即清掉、给停下的会话发话时清掉；停下后被中断的这一轮晚些落定（其间子 agent 来了审批）会把卡片落成空闲并被叫醒 | 钩子的 `waiting` 改为挂上一条、返回落定函数，会话池记着挂着的几条；卡片状态由底层状态（在跑、空闲、失败、已停等）加"有没有挂着的审批"算出；落定与叫醒看"人停下的"标记，不看卡片状态；已停下的再停不做事 |
| 完整取回之后从面板去掉，工作树与分支总留着（判断"没有改动"仍比对最初的起点） | 去掉时另认"完整取回之后再没有改动"（工作目录此刻正是上次取回时的快照）为没有改动，删工作树与分支；起点快照引用随之删 |
| 面板会话主 agent 的审批不带撤回信号，停下时排着的那条不撤回，批了照样执行 | 面板会话主 agent 的审批带上会话的撤回信号，停下（与去掉）即撤回；子 agent 的不撤回（它们接着跑）。撤回给模型的原因改为通用说法 `its agent was stopped`，消息区那一行写会话名 |
| 从壳里去掉的会话不在关掉 Pigeon 时等它释放完 | 会话池记着还在释放的，关掉时一并等（同在时限内） |
| 当前会话那张卡因子 agent 等审批标等待回应，偷看却不写在等什么 | 偷看照写 |
| 陈旧注释、`main-pool.test.ts` 没用的导入、已到不了的"已停的会话完整取回即删工作树"分支 | 改掉、删掉 |
| 480 写着"停下面板里的会话时子 agent 一并停下" | 480 标部分已改，指向 483；483 补上撤回审批、取回后清理与 `/resume` 的说法 |

未改：准备中的卡片在两下之间换了会话号（`pending:sN` 换成真会话号）时要按第三下；只在开得极快时碰上，不改。

补的测试：开运行面期间被停后发话与取回、在途但运行面报不在跑时发话与停下、跑完时子 agent 审批还挂着与几条一起挂着、停下后晚落定不被叫醒、去掉还在开的与关掉时等释放、停下的关掉时释放（`session-pool.test.ts`）；停下即撤回主 agent 的审批、完整取回之后没再改的去掉即删工作树、分支与快照引用、取回之后又改了的保留（`main-pool.test.ts`）。
