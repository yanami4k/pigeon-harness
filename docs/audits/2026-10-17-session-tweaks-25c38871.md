# 放手档显示成 auto、加 /new 开新会话（基线 25c38871）

两件小改，都在终端界面：把状态栏里放手那一档从 `yolo` 显示成 `auto`（决策 487），加一条 `/new` 开新会话（决策 488）。

## 一、改动

| 文件 | 内容 |
| --- | --- |
| `src/tui/status-bar.ts` | `modeLabel` 把 `yolo` 显示成 `auto`；醒目色按 `auto` 判断（`ask` 仍是暗色） |
| `src/tui/keybindings.ts` | `pigeon.toggleMode` 的说明改成 `Switch the approval mode (ask / auto)` |
| `src/tui/command-table.ts` | 加 `/new`：`scope: "session"`、运行中可用、不带参数 |
| `src/tui/commands.ts` | `CommandsHost` 加 `newSessionCommand`，分发 `/new`；给了参数写 `usage: /new` |
| `src/tui/shell.ts` | 选项 `newSession: { create }`；`newSessionConfigured()` 与 `newSessionCommand()`（走 `/resume` 同一道换手守卫、换手期间占住输入、失败落一行）；`rebindSession` 收 `source` 与 `resumed`，`/new` 用 `startup` 与花费从零 |
| `src/tui/main.ts` | `/new` 的装配：按当前会话所在的项目与审批模式建新会话核，`openCore({ deferSessionFile: true })`；等旧会话快照拍完；旧会话还在干活就 `retireToPanel`，否则 `closeCore(reason: "switch")`；换 `current`、跟随项目、接上新运行面 |
| 测试 | 新增 `src/tui/new-session.test.ts`（命令表规格、换绑与花费、给参数的用法、没有入口时的说明）；`approval-mode-shell.test.ts` 的显示断言改 `auto`；`input-queue.test.ts` 的运行中放行表加 `new` |
| 文档 | `docs/configuration.md` 的状态栏与斜杠命令两段；决策 487、488 与索引行；469 标部分已改 |

只改显示：`ApprovalMode` 仍是 `prompt` / `yolo`，会话记录里的 `pigeon.approval-mode`、注入快照、`--yolo`、`--sandbox-approval yolo|prompt` 与 `pigeon trace` 的写法都不动。

## 二、检查

- 本机：`tsc --noEmit`、`biome check src/tui`、定向测试（`new-session`、`approval-mode-shell`、`status-bar`、`keybindings`、`input-queue`）。
- 未做：整仓 `verify` 与慢档。本机 Windows 跑不动真容器那批（见 2026-09-30 全仓审计第一节），全量以验证服务器为准；这次改动到动手时为止没有过服务器。

## 三、已知限制

- `/new` 只在终端界面里有；`pigeon run` 与沙箱会话没有（沙箱沿用既有的 `/resume` 不可用与说明）。
- `/new` 的"旧会话退到面板"与 `/resume` 同一套判断：这一轮没完或它的子 agent 还在跑就退，闲着的直接关掉；面板那张卡随后按 485 的口径留在工作清单里。
- 显示改名不做迁移：既有会话记录里记的仍是 `yolo`，`pigeon trace` 照旧写 `yolo`，只有屏幕上那个词变成 `auto`。
