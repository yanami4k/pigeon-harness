# 子 agent 与会话的统一改造 · ⑧：所有会话一样（基线 da943b3）

457 剩下的四项之一：进程内的会话都是同一种，没有特殊的主会话；进入面板里的会话即它成为当前会话，原来的当前会话退到面板接着跑。斜杠命令分管整个程序的与作用于当前会话的；`/config` 与 `/reload` 对所有会话生效；`/resume` 换走还在干活的当前会话时它退到面板。细化记为决策 484。

## 二、工程上的取舍

- 换手不能做的时候：续接、回退、重读设置、手动压缩进行中，或这一轮已调了 `enter_worktree`、等收尾移进工作树时，进入面板里的会话答 `can't switch sessions right now`（`/resume` 同样）。移进工作树要在收尾时重建当前会话，换走了就移错了会话。
- 面板派出的会话不带 `enter_worktree`（本就在自己的工作树里）；启动与 `/resume` 打开的会话带着，退到面板后调它回一句它在后台。
- 面板里的会话照旧只跑 UserPromptSubmit，不跑 Stop 钩子；面板里在跑的一轮被接成当前会话后，跑完照当前会话的做法跑 Stop。
- 接过一个正在跑的会话时，消息区的历史取自会话记录，这一轮已经流出、还没写进记录的那一段不补，之后的增量照常接上。
- 换手时已经显示在审批区的那条审批保持原来的来源写法；卡片的"等待回应"只标在面板里时提出的审批。
- 面板里的会话重读设置：空闲时重建；重建期间又跑起来了就丢掉新开的运行面，等下次空闲再重建；它的子 agent 还在干活时每秒再看一次，等它们停下再重建。重建后的运行面与当前会话同一配方（带回退用的快照与任务清单）。
- 从当前会话退到面板的卡片：名字是会话名，那句话是它的首条输入；面板派出的照旧 `s1`、`s2`。
- 子 agent 的会话里打管整个程序的命令，先回到主视图再执行（`/memory` 这类的输出写在主视图的消息区里）。
- 面板输入框里打斜杠命令，同样先回主视图再执行（命令作用于当前会话，结果写在它的消息区里）。

## 三、已知限制

- 仍是进程内版：面板与会话同在一个进程，跨进程（关掉终端接着跑）不在这一块。
- 换手发生在等 UserPromptSubmit 钩子的那一刻时，钩子写的提示行落在换过去之后的消息区里。

## 四、检查

- 本机：`tsc --noEmit`、整仓 `biome check`、`dependency-cruiser`、`pigeon-paths-boundary`；`src/tui` 全部测试分三批跑过，`session-pool.test.ts` 跑过。

## 五、独立审查与修正

审查对照 da943b3 看了提交的改动，另写了场景测试复现。发现与处理如下。

| 发现 | 处理 |
| --- | --- |
| 这一轮落定后、收尾（Stop 钩子、移进工作树的重建）期间能换手：收尾钩子要接着跑时，续跑落到换过去的会话的运行面上（它在跑时会抛错、整个程序退出）；移进工作树的重建把壳拉回原会话、把工作树记进换过去的会话的记录 | 从这一轮落定到真正空闲之间（收尾钩子、afterTurn）不换手；Stop 循环开始时取定这个会话的运行面与钩子，每次等待之后看这一次工作的代号 |
| `/resume` 运行中放行后没走换手的守卫：两次 `/resume` 并发、压缩或重读设置进行中 `/resume`，会话核与壳各指一个、旧运行面没人释放 | `/resume`（含续接视图里选中）与进入面板里的会话同一道守卫：续接、回退、重读设置、压缩进行中、收尾期间都回 `can't switch sessions right now`；"原来的当前会话还在不在干活"改在目标会话开好之后再看；面板里一次只进一个 |
| 等 UserPromptSubmit 钩子期间换手，这一轮带走了换过去的会话的待用上下文，那个会话自己的丢了 | 开跑时就取定这一轮的运行面、钩子与待用上下文；钩子返回后若换过手，不再动壳上的上下文与消息区；被钩子拦下时待用上下文留给下一条 |
| 面板会话重读设置后的重建有竞态：用已释放的运行面开跑、重建期间跑完的一轮被新运行面丢掉、放弃新运行面时连带杀掉后台作业、两次重读给同一会话建两个运行面、排着重建时被进入就再没人重建 | 会话池加"独占一段"：重建期间不开跑、不叫醒、不能取出（进入回 `can't switch sessions right now`），发来的话排着、做完再发；去掉等它做完；同一个会话只排一次重建；放弃新运行面的那条路随之去掉；排着重建时被进入：没在跑的先重建再进入，在跑的在这一轮收尾时按当前会话重建；从当前会话退到面板时还没重建的，在面板里空闲时重建 |
| 在面板上中断当前会话时退回的排队内容，换手时被当作排着的输入交出，原会话一空闲就自动发出 | 单独交出（`held`），随会话核带着，回到它时放进输入框 |
| 两个会话核在同一个工作树里（一个在面板、一个是当前会话），从面板去掉前者会删掉后者正在用的工作树 | 去掉时本进程里还有会话持有这个工作树（在用锁的进程内计数）即保留 |
| `/resume` 打开新会话期间，钩子与 MCP 的提示前面多出 `[] ` | 还没起名的会话核照当前会话写，不加来源 |
| 交出去或接过来的一轮还在等 UserPromptSubmit 钩子时，Ctrl+X、Esc 挡不住，钩子之后照样开跑 | 换手时一并交出"停下"：面板里停下交出去的那一轮、壳里按 Esc 停下接过来的那一轮，钩子之后都不再开跑 |
| 换到别的工作树里的会话后，路径补全与 `@` 引用仍以启动时的工作区为根 | 跟着当前会话的工作区换 |
| 进入开到一半失败的卡片回 `session X is stopped` | 不是停下的回 `session X isn't open` |
| 469、286、340、442 的说法被 484 改动而没标 | 标部分已改，指向 484；484 补上不换手的情形与中断后退回的排队内容 |
| 文档写 `/take` 取回主工作目录 | 改为取回当前会话的工作区 |

未改，记为已知：

- 换手时已经显示在审批区的那条审批保持原来的来源写法，原会话的卡片也不补标等待回应（同二）。
- `/resume` 判断原会话"还在干活"只看这一轮与子 agent，不看它自己的后台作业（照 484 的定法）；闲着但有后台作业的当前会话被 `/resume` 换走时，后台作业随运行面释放而停。
- 退出时的工作树清理：当前会话是面板派出的会照 445 问，`--worktree` 会话退到面板后由面板不问地清理；工作清单跨重启之后（⑨）退出时清单里会话的工作树一律保留，这处随⑨一并改。

补的测试：`session-handoff.test.ts`（收尾期间不换手、`/resume` 同一道守卫；钩子期间换手不串上下文、交出去的一轮停下即不开跑；中断后退回的排队内容单独交出；会话池独占一段）。
