# 子 agent 与会话的统一改造 · ⑧：所有会话一样（基线 da943b3）

457 剩下的四项之一：进程内的会话都是同一种，没有特殊的主会话；进入面板里的会话即它成为当前会话，原来的当前会话退到面板接着跑。斜杠命令分管整个程序的与作用于当前会话的；`/config` 与 `/reload` 对所有会话生效；`/resume` 换走还在干活的当前会话时它退到面板。细化记为决策 484。

## 二、工程上的取舍

- 换手不能做的时候：续接、回退、重读设置、手动压缩进行中，或这一轮已调了 `enter_worktree`、等收尾移进工作树时，进入面板里的会话答 `can't switch sessions right now`（`/resume` 同样）。移进工作树要在收尾时重建当前会话，换走了就移错了会话。
- 面板派出的会话不带 `enter_worktree`（本就在自己的工作树里）；启动与 `/resume` 打开的会话带着，退到面板后调它回一句它在后台。
- 面板里的会话照旧只跑 UserPromptSubmit，不跑 Stop 钩子；面板里在跑的一轮被接成当前会话后，跑完照当前会话的做法跑 Stop。
- 接过一个正在跑的会话时，消息区的历史取自会话记录，这一轮已经流出、还没写进记录的那一段不补，之后的增量照常接上。
- 换手时已经显示在审批区的那条审批保持原来的来源写法；卡片的"等待回应"只标在面板里时提出的审批。
- 面板里的会话重读设置：空闲时重建；重建期间又跑起来了就丢掉新开的运行面，等下次空闲再重建；它的子 agent 还在干活时每秒再看一次，等它们停下再重建。重建后的运行面与当前会话同一配方（带回退用的快照与任务清单）。
- 从当前会话退到面板的卡片：名字是会话名，那句话是它的首条输入；面板派出的照旧 `s1`、`s2`。
- 子 agent 的会话里打管整个程序的命令，先回到主视图再执行（`/memory` 这类的输出写在主视图的消息区里）。
- 面板输入框里打斜杠命令，同样先回主视图再执行（命令作用于当前会话，结果写在它的消息区里）。

## 三、已知限制

- 仍是进程内版：面板与会话同在一个进程，跨进程（关掉终端接着跑）不在这一块。
- 换手发生在等 UserPromptSubmit 钩子的那一刻时，钩子写的提示行落在换过去之后的消息区里。
