## 二、与启动时确认共用的代码、确认记在哪

- 打开别的工作区的会话读它的设置走 `openSessionSettings`（`src/application/session-settings.ts`），确认方式用它的 `interactive`，只是 `ask` 换成界面里的确认区（`askTrustPanel`）：要确认哪些条目（`pendingTrustEntries`：信任目录、指纹比对）、信任时记下（`recordTrustedEntries`）、这次不用时把条目从快照里去掉（`withoutTrustEntries`）都是启动时的同一套。界面里列的每一条用 `describeTrustEntry`，开头一句与启动时同一个常量（`TRUST_PROMPT_HEADER`）。
- `/reload` 重读别的项目时走 `planSettingsReload` 与 `applySettingsReload`（与当前项目的 `/reload` 同一套），确认同样用界面里的确认区，信任时 `recordTrustedEntries`。
- 确认记在用户级的 `~/.pigeon/state/config-trust.json`（按项目规范化路径与条目键记指纹），与启动时的确认同一处、效果相同：之后在那个项目里启动 Pigeon 不再问。

## 三、工程上的取舍

- 清单文件畸形按空清单（是程序状态，下次写入即重写），不像确认记录那样响亮失败：清单坏了不该挡住开面板。
- 本进程没开的卡片在打开面板时读一次（读会话记录取名字、首条输入与最后一条回复），之后不随会话记录变化刷新；重开面板即重读。
- 卡片上的目录只标在不属于当前会话所在项目的会话上（写它的工作区，`~` 缩写）。
- 别的项目的设置快照按项目缓存，同一项目的会话共用；`/reload` 重读别的项目时，确认即记下（不等那些会话重建完），重建在各自空闲时进行。
- 别的项目的会话用它自己项目的子 agent 类型；打转检测、子 agent 上限按它自己项目的设置。键位、设置面板、← 开面板与收尾钩子上限跟着当前会话所在项目的设置。
- 打开清单里的会话沿用当前会话的审批模式（同 469 的派出）。

## 四、已知限制

- 仍是进程内版：别的进程开着的会话只能看历史，不能在这里接着干。
- `main.ts` 里打开清单里的会话、重读别的项目的设置、退出时保留工作树这几段没有单元测试（入口不可单测）；拆出的数据源、索引与界面部分有测试。

## 六、独立审查与修正

审查对照 17df283 看了提交的改动并跑了新加的测试。发现与处理如下。

| 发现 | 处理 |
| --- | --- |
| 启动项目里在面板派出的会话带着派出时的设置快照，`/reload`、`/config` 改不到它；进入它之后重建的运行面用新快照，但留着的快照还是旧的，退回面板再重建会回退 | 启动项目里的会话不带快照（用本进程的，`/reload` 换新的）；换上某个项目的新快照时，带着这个项目快照的会话一并换上 |
| `/reload` 列出待确认的条目之后换到别的项目的会话，`/reload confirm` 会把前一个项目的设置套到这个项目的会话上 | 待确认的计划记着项目；确认或跳过时项目不对即作废，回 `the pending reload is for another project; run /reload again` |
| 当前项目设置没变时（回 `settings unchanged`）完全不重读别的项目 | 重读别的项目改为每次 `/reload` 做完都做（等确认时不做） |
| 打开清单里的会话没有防重入：偷看发话与进入同时触发会在本进程开出两份，前一份泄漏，同一项目弹两次确认 | 同一个会话同时只开一次、同一个项目的设置同时只读一次（进行中的复用） |
| 准备中被去掉的会话开好后仍记进清单、工作树留着，下次面板又出现 | 会话池关掉被去掉的会话时说明是去掉；面板会话据此删出清单、工作树按有没有改动清理 |
| 没有开着会话的别的项目的设置快照不随 `/reload` 失效 | `/reload` 时丢掉这些快照，下次打开那边的会话时重读 |
| `/worktrees` 能不能用仍按启动的目录判断 | 执行时按当前会话所在的仓库判断（不是 git 仓库回 `not a git repository`） |
| Windows 上 `/take` 的跨仓库判断大小写敏感，同一目录写法差大小写即判成别的仓库 | 改用 `realpathSync.native` 并在 Windows 上不分大小写 |
| 面板里重建别的项目的会话会改写当前会话 `/memory` 的上限 | 面板里的会话重建用它自己的那份上限 |
| 从没建过会话文件的会话（启动后一句话没说就 ← ←）留下永远列不出来的行，清单越积越多 | 还没有会话文件的不记；记进清单时顺手去掉会话文件已不在的别的行 |
| 风险：开清单里的会话途中关掉 Pigeon，开好的运行面收进已关掉的面板、没人释放 | 每个等待之后看是不是在关；在关即释放，不收进面板（工作树留着） |
| 开着的别的项目的会话卡片不标目录 | 同样标 |
| 换会话时键位不跟着换 | 跟着当前会话所在项目的设置重装 |
| 偷看发话开起来的会话卡片丢了首条输入 | 带上 |
| 卡片目录的 `~` 缩写没用注入的家目录 | 用注入的 |
| 483、442 被 485 改动而没标 | 标部分已改，指向 485；485 补上别的项目确认即记下的时机、待确认计划跨项目作废与还没建会话文件的不进清单 |

未改，记为已知：

- 打开面板时同步读清单里每个本进程没开的会话记录（取名字、首条输入与最后一条回复）并查会话锁；清单很长、会话记录很大时打开面板会慢一下。
- 面板派新会话时"是不是共用目录"与"开在哪个项目"分两次取当前会话，两次之间换了会话的极端情况下会按前一个项目判共用目录。
- 界面里的确认在审批区被占着时（按理不会发生：两者走同一个排队）按这次不用处理，结果随那个项目的快照留到进程结束或下次 `/reload`。
- 从面板或只读视图里打 `/panel` 会再记一次当前会话（已在清单里，只多写一次）。

补的测试：`settings-reload.test.ts`（待确认计划跨项目作废、没变化也做之后那一步）、`session-index.test.ts`（记进时去掉失效的行）、`session-pool.test.ts`（去掉还在开的会话时说明是去掉）、`work-list.test.ts`（开着的别的项目的会话标目录、开起来带首条输入）。
