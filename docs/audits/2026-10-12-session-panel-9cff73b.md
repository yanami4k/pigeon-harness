## 一、改了什么

- 新文件 `src/application/session-pool.ts`：
  - `SessionPanelSource`：面板与会话之间的面——`list`（卡片：名字、状态、派它时的话、摘要、等待的事、失败原因、工作树、时间）、`subscribe`、`spawn`、`send`、`stop`、`peek`、`take`。卡片是纯数据、动作都是按会话号的调用，不假设会话与面板同在一个进程（以后换成常驻托管进程、各会话独立进程时实现同一接口）。
  - `LocalSessionPool`（进程内版）：派出即在跑，跑完空闲、摘要取最后一条有文字的助手回复的开头（压成一行、120 字）；运行失败、开运行面失败记为失败；审批挂上与落定由运行面的包装通知（`PooledHooks.waiting`）；在跑或等待回应时不收新话；停下先中断再释放运行面，之后只读；`closeAll` 全部停止、之后不能再派。排序：等待回应、在跑、空闲、失败、已停，组内按更新时间新的在前。进入会话要直接订阅运行面，是进程内版独有的，由 `runtimeOf(id).live` 给出。
  - `takePooledChanges`：`/take` 用 worker 取回的叠回（`overlayWorkerChanges`）把会话工作树相对起点的改动叠回主工作目录，写明取回的、叠不上的、会话删了而没删的、过大没取回的。
- 新文件 `src/tui/main-pool.ts`：派出时新会话号、建独立工作树（`openNamedWorktree`，名字为"面板里的名字-会话号末六位小写"，起点缺省远端默认分支）、按与主会话同一条装配路径开运行面（工作区为工作树，取主会话当前的设置快照，带联网工具与记忆写入，不带派 worker 的工具）；审批处理口包一层：挂上时告诉会话池"在等 工具名 参数摘要"，请求上标 `sessionId` 与 `pooled: { name }`，落定后清掉；停下时释放运行面、按 445 的规则清理工作树（没有改动即删，有改动保留，不问）。
- 审批来源：`ApprovalRequest.pooled`；`approvalSourceLine` 对它写"来源：会话 名字 ｜ 会话号 …"。
- 新文件 `src/tui/session-panel.ts`：整屏面板（按状态分组、光标、偷看区、说明行、超出一屏按光标滚动），文字一律 036 净化、压成一行。
- `src/tui/shell.ts`：视图 `panel` 与 `pooled`；选项 `pool`（`TuiPoolFace`）；`/panel`；面板按键（上下选、输入框为空时空格偷看与回车进入、连按两次 Ctrl+X 停止、Esc 先关偷看再关面板）；面板里的输入偷看时发给选中的会话、否则派新会话；进入的会话里输入发给它、状态行写它的状态，Esc 回面板；面板与进入的会话里斜杠命令不执行（提示 Esc 回主会话再用）；`/take <名字>` 是面板里的会话时取回它的改动。会话池有变化即重画。
- `src/tui/command-table.ts`、`commands.ts`：登记 `/panel`（运行中可用）；`/take` 用法写上"会话面板里的会话"。`src/tui/main.ts`：非沙箱会话建会话池并交给壳；退出时先全部停止（工作树的说明打到标准错误输出）。
- 文档：`docs/configuration.md` "终端界面"一节加"会话面板 `/panel`"。

## 四、自定的细节

- 入口：`/panel`（不与 `/agents` 树形视图、`/sessions` 会话列表冲突）。没有绑快捷键。
- 名字：`s1`、`s2`……按本进程派出的先后；工作树名字另加会话号末六位，避免与上次进程留下的同名工作树混用。
- 起点：工作树起点缺省远端默认分支（与 `--worktree` 一致）；没有远端即当前 HEAD（S3 的既有取法）。
- 派出的会话不带派 worker 与脚本编排的工具；记忆写入与联网工具照主会话。
- 停止：连按两次 Ctrl+X（间隔 1.5 秒），参照 Claude Code agent view；停下的会话留在面板里（已停），不删工作树（按 445：没有改动即删，有改动保留）。
- 回复：偷看时输入框里的话发给选中的会话；进入的会话里输入同样发给它。会话在跑或等待回应时不收（不排队），说明原因、话留在输入框。
- 进入会话：消息区换成它的对话（历史取自会话文件，之后订阅它的运行事件、流式正文与工具结果实时投影，与主会话同一套投影）；Esc 回面板。进入的会话里没有双击 Esc 回退（单击即回面板）。
- `/take` 沿用 worker 取回的叠回：行尾按检出规则（本机 `core.autocrlf=true` 时写成 CRLF），与取回 worker 相同。
- 关掉 Pigeon：先跑主会话的 SessionEnd，再停全部面板会话，之后照旧收尾主会话。

## 六、审查修正（20f07d4 之后）

### 改了什么

1. 审批可见：面板与进入的会话两个视图同样写审批块（含来源行），面板加上状态行（审批挂着时说明审批，平时写会话数与按键）。审批或扣住的消息挂着时，编排按键入口先让给模态（既有的吞键约定），字母不进输入框。
2. 开运行面期间被停：开好之后先查卡片是否已停（或面板已关），是即释放运行面、不开跑。
3. 运行失败：运行面 `run` 正常返回但 `status` 为 `failed` 时卡片记为失败，原因取 `errorMessage`。
4. `/resume` 与会话选择器排除面板里还开着（没停）的会话，`/resume` 写明原因（`ResumeViewHost.pooledSessionIds`）。
5. 钩子：面板会话开好后跑 SessionStart（补的上下文作第一条输入的前缀），每次发话前跑 UserPromptSubmit（拦下即这一轮失败、写明"输入被钩子拦下：…"；补的上下文作前缀），停下时跑 SessionEnd。
6. 工作树：开着期间持有在用锁（`holdWorktreeInUse`，停下释放）；起点按设置的 `worktree.baseRef`（`head` 时不取远端）。
7. 打转检测（同主会话的设置，叫停即中断这一轮）、后台作业通知（`jobNotices.bind`：通知写明来源，空闲时叫醒——会话池新加 `wake`，空闲或失败时只带通知跑一轮）、钩子与 MCP 的提示（写明来源会话）都挂上。
8. 关掉：`closeAll` 先等还在开的开完再停，整体限时 15 秒（可配），没在时限内停下的如实返回，退出时打到标准错误输出。
9. 退回排队内容的键在面板与进入的会话里不动主会话排队的话。
10. `/take`：完整取回（没有叠不上、会话删掉、过大没取回的）之后，还开着的会话把起点前移到取回时的样子（`snapshotWorkdir` 在 `refs/pigeon/panel/<工作树名>` 下钉住），已停的会话删掉工作树与分支（同 448）；工作树已不在或已删时如实说明；面板会话与 worker 同名时要求写 `会话:<名字>` 或 `worker:<名字>`。
11. 派出：卡片先以"准备中"出现；取远端在后台进行（`prefetchWorktreeBase`：与同步取法同一个"超过 24 小时才取"的判断，限时、不许交互；取不到即改从 HEAD 起并说明），之后建工作树不再同步 fetch。
- 建议项：偷看只列人说的话与回复（沿用回退的判法：状态块、程序通知、作业通知、会话间消息、续跑提示都不列）；`send`、`peek`、`take` 改为异步（面板的偷看内容取回来先存着再画）；面板上主消息区看不见的提示（如 Ctrl+C 的"再按一次退出"）同时写在面板说明行；Ctrl+O 对进入的会话生效；壳停止时退订进入的会话。没有做的：记忆写入提示与 Notification 钩子不标来源会话、卡片上不显示花费（见尚待确认）。
