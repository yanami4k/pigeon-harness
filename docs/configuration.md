# 配置与状态目录

本页说明 Pigeon 的设置文件、程序状态目录、记忆与人写的说明、推理档位、模型请求的失败重试、模型信息、上下文压缩、撞上限续跑与流式重复检测、迁移命令与配置相关的安全防线（决策 325、326、328–332、340、341、362、367、390、420、422、424、431、432）。

## 三层设置

| 层 | 位置 | 是否提交 |
| --- | --- | --- |
| 用户级 | `~/.pigeon/settings.json` | 不在项目里 |
| 项目共享 | `.pigeon/settings.json` | 可提交 |
| 项目个人 | `.pigeon/settings.local.json` | 不提交 |

优先级：项目个人 > 项目共享 > 用户级。合并规则：对象按键逐层合并，标量与数组由高优先层整体替换；例外是 `permissions` 一节：放权规则三层并集生效（项目共享层的规则须先经确认，见下文第三道防线）。

在主目录下启动（项目根就是主目录，或项目的 `.pigeon` 链到 `~/.pigeon`）时，项目级的 `.pigeon` 与用户级的 `~/.pigeon` 是同一个目录、同一批文件，按一层（用户级）处理：设置只读用户级与项目个人两层，`trustedDirectories` 这类只许写在用户级的项照常可写，`/config` 不会报"被项目设置覆盖"；学到的记忆只有用户级一层（`/memory` 只列这一层，`/memory edit project` 回一句改用 user，`update_memory` 写项目级即拒绝）；Skill 只按用户级扫一次；迁移命令（`pigeon migrate-config`）按用户级校验，写明写进去的对所有项目生效。

设置在会话开始时读一次，形成本会话的设置快照；会话中途改文件不生效，下次启动或在终端界面里 `/reload` 之后才生效（见下文）。沙箱会话与会话面板派出的会话沿用开出它的会话的快照。

设置文件与 `.mcp.json` 开头的 UTF-8 字节序标记（BOM）忽略。文件不是合法 JSON、出现未知键（顶层或节内）、写了 key、项目级写了 `trustedDirectories`，或合并后不成立（例如打转检测的三个轮数不递增），启动时报错并指出文件、键与所在层。写了已删的设置（`messaging`、`orchestration` 两节，`commands` 里的 `roles`）同样开局报错，写明是哪个文件的哪一项已删、请删掉（决策 478）。整个文件可以有一个 `$schema` 键。

## 沙箱资源上限

`sandbox` 一节可给容器设三项资源上限：写 `0` 为不限，不写取缺省。

- `memory`：内存上限，`0` 或数字加单位 k/m/g/t（不分大小写，按 1024 进位，如 `"8g"`、`"512m"`）；交换区不另占（`--memory-swap` 取同值）。缺省为 Docker 所在机器内存的一半（取 `docker info` 的 MemTotal，向下取整到 MiB；读不到时本次不设内存上限并说明）。低于 6m（Docker 的下限）报错。
- `pids`：进程数上限，非负整数；缺省 4096。
- `cpus`：CPU 核数上限，非负数（可带小数）；缺省不限。

设了内存上限时，执行端在每条命令前后读容器 cgroup 的 oom_kill 计数：计数增加即报"超出沙箱内存上限 <数值>"（agent 在 `run_command` 的结果里看到，人另收到一行提示）；读不到计数而命令以退出码 137 结束时报"可能超出沙箱内存上限 <数值>"。

## 按环境注册的工具

会话开始时按当前环境决定注册哪些工具，只做本地检查（不发请求）：没有可用的搜索后端（缺 key）不注册 `web_search`；本会话所在的会话树（沿分叉关系上溯到最上层，连同各级分叉）以外没有会话时不注册会话检索三件——与检索的排除口径一致，没有合法文件头的空会话文件不算，文件头之外只有钩子运行记录、从没开始过对话的会话也不算（决策 432）。检查在会话开局做一次，工具清单在一次会话内固定：终端界面里 `/reload` 不改变按环境判断的结果，改了搜索后端只提示一行"重启后生效"。这只针对按环境的自动判断；设置里的联网总开关 `web.enabled` 是使用者主动的开关（例如出于隐私临时关掉联网），`/reload` 之后照旧按新设置增删 `web_search` 与 `web_fetch`（见下文"联网工具的开关"）。新开会话时重查 git 仓库与历史会话；key 取自 Pigeon 进程的环境变量，改了要重启 Pigeon 才生效。开局没注册 `web_search` 时在终端提示一行原因。每次运行开始的记录里写明实际注册的工具，以及没注册的工具与原因，`pigeon trace` 也显示。

## 联网工具的开关

`web_search` 与 `web_fetch` 在终端界面（含续接）与 `pigeon run` 中缺省注册。下面三者任一成立就不给这两件工具：两件都不注册，系统提示里也不出现介绍联网工具的那一句。

- 设置 `web.enabled` 为 `false`（布尔，缺省 `true`；三层按标量覆盖，高优先层说了算）。
- 启动参数 `--no-web`：只对本次运行生效，与 `--no-hooks`、`--no-subagents` 的写法一致；各入口都接受。
- 沙箱断网档（`--sandbox --sandbox-network off`）。

没有可用的搜索后端（缺 key）时只注册 `web_fetch`，系统提示里换成只讲 `web_fetch` 的一句（见上文"按环境注册的工具"）。

终端界面里 `/reload` 之后按新设置重算。

```json
{ "web": { "enabled": false } }
```

## 单轮输出上限

不配置时 Pigeon 不另设单轮输出上限：按模型定义的上限发，由 provider 按剩余上下文收窄。自带的 DeepSeek 接入按官方上限 393,216 发。"模型定义没有上限（`maxTokens` 缺失或不为正）时发 32,000"只适用于第三方模块自构的模型对象，不涉及自带的 DeepSeek。启动参数 `--max-output-tokens <n>` 设了上限时，取它与模型上限中较小的那个；设了的值记进注入快照与运行开始条目的 model 段，没设的不记（表示跟模型）。

经 `--stream-fn` / `PIGEON_STREAM_FN` 接入的第三方模块，交给 provider 的模型对象须带 `maxTokens`（模型的单次输出上限）：Pigeon 交给模块的只是身份占位，看不到模块里的真实模型对象，不配置上限时就按模块自己的模型对象发。

## 模型请求的失败重试

每次模型请求（交互与无人值守的主请求、压缩摘要、网页提炼）都把重试次数交给 pi-ai（决策 420）。重试的规则是 pi-ai 自带的、与官方 SDK 一致的那套：连接失败与 408、409、429、5xx 重试，服务方给了 Retry-After 就照它等（超过 60 秒不等、直接报错），否则指数退避；400 等请求本身有错的不重试。只覆盖开始收回复之前的失败，回复流中途断开不重试。

次数在 `modelRequest` 一节设，缺省 4，写 `0` 为不重试：

```json
{ "modelRequest": { "maxRetries": 2 } }
```

每次重试在会话记录里写一条 `pigeon.request-retry`（第几次重试、上一次的 HTTP 状态码，连接失败时记错误文字、两次之间实测等待的毫秒数），`pigeon trace` 与 `pigeon replay` 各列一行。记录靠接管请求选项里的 `fetch` 得来，只在接入模块声明的线路（`modelInfo.api`）为 `anthropic-messages`、`openai-completions`、`openai-responses`、`azure-openai-responses` 时进行（自带的 DeepSeek 接入声明 `anthropic-messages`）；pi-ai 的 Google 线路不接受自带的 `fetch`，其余线路照样重试，只是不记。第三方模块须把调用选项原样转交 pi-ai，重试次数与记录才生效。

## 推理档位（思考）

Pigeon 缺省开思考（决策 390）：模型信息表明支持推理（`reasoning` 为真）的模型，缺省档位为 `high`；不支持推理或不知道是否支持的模型缺省为 `off`，不发任何思考参数，行为与以前相同。是否支持推理按下文"模型信息"的取法定；自带的 DeepSeek 接入声明支持推理，缺省即开思考。

档位可选 `off`、`minimal`、`low`、`medium`、`high`、`xhigh`、`max`。取值优先级从高到低：

1. 启动参数 `--thinking <档位>`，例如 `--thinking off`：只对本次运行生效；终端界面（含 `pigeon resume`）与 `pigeon run` 都接受。
2. 设置 `thinking.level`（三层按标量覆盖，高优先层说了算），长期关掉思考：

   ```json
   { "thinking": { "level": "off" } }
   ```

3. 都没给时按模型信息定缺省（上面的 `high` 或 `off`）。

档位在运行面装配时定一次（续接与 `/reload` 时重新定），冻结进注入快照，写进每个 Run 开始条目 model 段的 `thinkingLevel`。

档位为 `off` 时，对支持推理的模型显式发"关思考"（DeepSeek 不发思考参数即缺省开思考，所以要关必须显式发）；对不支持推理的模型什么都不发。`web_fetch` 的内容提炼是单独的请求，不请求思考，不受档位影响。压缩摘要通常沿用原会话发出，思考档位同主请求；只有单独组装的摘要请求不请求思考（见下文"上下文压缩"）。

开思考的影响：

- **花费**：思考内容按输出计价。同一会话里以前各轮回复的思考随之后的每次请求作为输入交给模型（不变的前缀多按缓存命中价计），上下文涨得更快，自动压缩更早触发。自带的 DeepSeek 接入把签名为空的思考也照样作为思考块交回，不改成普通文字。
- **等待**：每轮先生成思考再给回答或工具调用，回得更慢。
- **温度**：开思考时 Pigeon 不下发采样温度（DeepSeek 思考模式下设了温度不报错也不生效），Run 开始条目记"请求了但未生效"与请求值。档位为 `off` 时照常下发。同一道题多次运行的出入因此可能变大。
- **输出上限**：开思考时 pi-ai 按档位另算一份思考预算（`minimal` 1,024、`low` 2,048、`medium` 8,192、`high` 及以上 16,384 token），配置了单轮输出上限 n 时实际请求的 `max_tokens` 为 n 加预算（不超过模型上限），思考与回答共用它；没配置时仍按模型上限发。
- **档位的区分**：自带的 DeepSeek 接入走 Anthropic 兼容端点，pi-ai 把档位换算成上面的思考预算（`budget_tokens`）发出；DeepSeek 文档写明该端点忽略 `budget_tokens`、思考强度缺省为 high，所以在 DeepSeek 上 `off` 以外的各档效果相同。

## 模型信息

Pigeon 为每次运行确定所用模型的价格、上下文窗口、单次输出上限、是否支持推理与接受的输入类型，并查出该服务方的提示缓存规则（决策 362）。这些信息写进每个 Run 的开始条目（`modelInfo`，每一项带来源），供上下文裁剪等功能查询。上下文压缩所用的模型窗口取自其中的窗口（决策 422，见下文"上下文压缩"）。是否支持推理决定缺省的推理档位（见上文"推理档位（思考）"）；输入类型含 `image` 时模型能看图，`read_file` 据此把图片交给模型（决策 414，见下文"读档工具：图片与二进制文件"）。

模型身份：接入模块声明了 `provider` 与 `id` 就用声明的，否则用启动参数 `--provider`、`--model` 的标签。

价格、窗口、输出上限逐项取值，优先级从高到低：

1. 设置 `modelInfo.models` 里该模型的手填值（来源记为 settings）；
2. 接入模块声明的（declared）；
3. 按 provider 与模型名查 pi-ai 自带的模型目录（catalog；价格为美元/百万 token）；
4. 都没有记为未知（unknown）。

是否支持推理（`reasoning`）只有声明与目录两层，设置里不覆盖它（要改档位直接设 `thinking.level`）。输入类型（`input`，取 pi-ai 模型对象的同名字段，`["text"]` 或 `["text", "image"]`）同样只有声明与目录两层；都没有时按只收文字处理。

每一项单独取：价格可以来自目录，窗口来自声明。价格的四个数（`input`、`output`、`cacheRead`、`cacheWrite`，每百万 token）与币种 `currency` 算一项，整体取自同一来源；四个数全为 0 的一层当作没给价格，继续往下层取。pi-ai 目录加载失败时打一行告警，未声明的项按未知处理，不影响启动。

### 接入模块声明模型信息

`--stream-fn` / `PIGEON_STREAM_FN` 指向的模块除默认导出的 StreamFn 外，可以再具名导出 `modelInfo`，字段取 pi-ai 模型对象的那一套，另可写实际服务方 `servedBy`，各项可缺省（直接导出一个 pi-ai 模型对象也可以；既不是 pi-ai 模型字段、也不是 `modelInfo` 字段的顶层键不用，启动时打一行告警）：

```js
export default streamFn;
export const modelInfo = {
  provider: "acme",
  id: "acme-large",
  cost: { input: 2, output: 8, cacheRead: 0.2, cacheWrite: 2.5, currency: "USD" },
  contextWindow: 256000,
  maxTokens: 32000,
  reasoning: true,
  input: ["text", "image"],
};
```

`currency` 缺省为 USD。不导出 `modelInfo` 的老模块照常可用；导出了但字段不合规，启动时报错并指出字段。价格、窗口、输出上限、是否支持推理与输入类型都声明了就不加载 pi-ai 目录。自带的 DeepSeek 接入声明官方人民币非高峰价（`currency` 为 CNY；高峰加价由计费另算）；它交给 pi-ai 的模型对象价格仍为 0，现有的花费计算与状态栏不变。它按服务商文档声明 `deepseek-flash` 能看图（`input` 为 `["text", "image"]`，交给 pi-ai 的模型对象与声明取同一份，否则 pi-ai 发请求前会把图片换成占位文字），其他型号只收文字。

### 设置里的覆盖值

`modelInfo.models` 的键是 `"<provider>/<模型名>"`（按上面的模型身份匹配，不合这一格式的键报错），值可写：

- `cost`：四个价格与 `currency` 须写全（三层按键合并，币种必填才不会沿用低层的币种）；
- `contextWindow`、`maxTokens`：正整数；
- `cache`：缓存规则的覆盖。`servedBy` 指明按哪家服务方的规则查表（经代理或兼容端点访问时用），`mode`（auto、explicit、both、none）、`minPrefixTokens`，以及 `short`、`long` 两档的 `seconds`、`basis`、`refreshOnHit`、`writeMultiplier`、`readMultiplier`，写了的项逐项盖在表里查到的规则上。

```json
{
  "modelInfo": {
    "models": {
      "my-proxy/claude-sonnet-5": {
        "contextWindow": 200000,
        "cache": { "servedBy": "anthropic" }
      }
    }
  }
}
```

### 缓存规则表

缓存规则按实际服务方查，不按接口格式（经 Anthropic 兼容端点访问 DeepSeek，查的是 DeepSeek 的规则）。实际服务方的取法：设置里的 `cache.servedBy` > 声明里的 `servedBy` > 按声明的 `baseUrl` 主机名查已知服务方（如 `api.deepseek.com`、`api.anthropic.com`、`api.openai.com`）> provider 标签。同一服务方下可再按精确型号或模型名前缀细分；有的服务方没有兜底行，表里没列出的型号各项未知。每行记缓存方式、短长两档的保留时长（秒数或未知，依据类别为 fixed、minimum、typical、best-effort 或 unstated）、命中是否续期、写缓存与命中按输入价的倍数、如何开启、最小可缓存前缀，以及出处（URL、取用日期、原文引句）。查不到的服务方各项记为未知，由用到它的功能各自保守处理。

表的出处可手动复核：`node scripts/check-cache-rule-sources.ts` 逐行抓取出处页面，确认原文引句还在，不在的行标为"需复核"并列出（需要经代理上网时另设 `NODE_USE_ENV_PROXY=1`）。这个脚本不进 CI。

## 给模型看的文字

- 给模型看的文字一律是英文（决策 428）：系统提示、工具说明与参数说明、开工状态块与状态更新、工具结果与报错、给模型的通知。给人看的界面、提示与报错是中文。模型照系统提示用使用者的语言回答。
- 系统提示开头写明所用模型（决策 429）："You are Pigeon, a coding agent powered by the <模型 id> model"。模型 id 取本次的模型信息（接入模块的声明，没有则取启动参数 `--model`）；只有占位标签 `custom` 时省掉这半句。做事规矩与工具用法只写本会话实际有的工具。
- 系统提示整场会话逐字节不变；续跑时所用模型与上一个 Run 记下的不同，按新模型重建（决策 430）。
- 续跑决策 428 之前的旧会话：开工状态块各节第一次整段重发一次（节名改成了英文，旧记录里的中文节名认不出），之后照常只追加变了的节；旧记录里的中文通知前缀、文件变化一段与拒绝理由照样认得。

## 撞上限续跑与流式重复检测

两项都缺省开启，各入口（终端界面含续接、`pigeon run`、`/fork`）行为一致。

**续跑**（`truncationContinuation`）：一条回复因输出上限截断、且没有工具调用时，本次运行不收尾：从发给模型的上下文里去掉这条回复，追加一条英文提示（大意：上条回复被截断、未执行任何工具，不要重复前文，简短说明下一步并直接发出一个工具调用；决策 455 之前的会话里是中文，回看时照样认出），然后接着跑。截断的回复照留在会话文件里，但移出主分支（会话树的叶子退回它之前），续跑（`pigeon resume`、`/resume`）与分叉按主分支还原的上下文同样不含它；主分支上它的位置是一条续跑记录（`pigeon.continuation`：截断的来由、本次运行第几次、连续第几次与截断回复的用量），其后是那条提示；轮数、用量与花费的统计（`pigeon run` 的结果、会话列表）按续跑记录把截断的回复计回。回看历史时这条提示标明为续跑提示；打转检测不把截断的那一轮算作一轮。截断里带工具调用的照旧：工具调用判为未执行、提示重发。计数与打转检测分开。

| 键 | 缺省 | 说明 |
| --- | --- | --- |
| `enabled` | `true` | 开关 |
| `maxConsecutive` | `2` | 连续续跑的上限；中间有一条回复没触发续跑即清零 |
| `maxPerRun` | `5` | 一次运行（一次 `pigeon run`、终端界面里的一次提问）合计续跑的上限 |

用尽即照原样收尾（以截断的回复结束，终态完成、停止原因 length）。

**流式重复检测**（`repetitionGuard`）：包在模型调用外层，与服务商无关；只看正文与思考，不看工具参数。判据两种：

- 逐字周期：每收到 `checkIntervalChars` 个新字符，看最近 `windowChars` 个字符的末尾是否由同一单元首尾相接重复构成。单元不超过 `maxPeriodChars`，须含文字（纯标点、数字、空白不算）；单元不超过 `shortPeriodChars` 的要重复 `shortMinRepeats` 遍且覆盖 `shortMinRepeatedChars` 字，更长的要重复 `minRepeats` 遍且覆盖 `minRepeatedChars` 字。
- 段落相似度：按空行切段（没有空行时到 `segmentMaxChars` 强制切），去掉标题行后不含空白不足 `segmentMinChars` 个字符的段不计；每段与最近 `segmentWindow` 段比较词三元组的相似度（中日韩文字逐字成词），达 `similarity` 算近似；攒满 `minSegments` 段之后，近似段（含本段）达 `minCluster`、且最近连续 `minConsecutive` 段每段都与前一段近似才命中（防只差编号、人名的模板段误判）。

`mode` 为 `abort`（掐断，缺省）时，命中即中止本条回复，截至命中处的内容以停止原因 length 收尾、交给上面的续跑；为 `log`（只记录）时照常转发，本条回复里同一通道的同一判据只记第一次。每次命中写一条会话记录（`pigeon.repetition`：判据、通道、周期长度、重复次数、起点、触发位置与模式；位置是本条回复里该通道的字符偏移，字符按 UTF-16 码元计）。

`preset` 选参数的底子，节里单独给的参数覆盖它：

| 参数 | `omp`（缺省） | `wide`（试跑用） |
| --- | --- | --- |
| `checkIntervalChars` | 128 | 128 |
| `windowChars` | 4096 | 49152 |
| `maxPeriodChars` | 1024 | 16384 |
| `minRepeats` / `minRepeatedChars` | 3 / 1024 | 3 / 2000 |
| `shortPeriodChars` / `shortMinRepeats` / `shortMinRepeatedChars` | 60 / 4 / 180 | 0（不分短周期）/ 4 / 180 |
| `similarity` | 0.8 | 0.8 |
| `segmentMaxChars` / `segmentMinChars` | 700 / 60 | 700 / 60 |
| `segmentWindow` / `minSegments` / `minCluster` | 16 / 8 / 4 | 16 / 8 / 4 |
| `minConsecutive` | 3 | 3 |

`omp` 档照 oh-my-pi 的同名检测（段长按字符计与 `minConsecutive` 是 Pigeon 另加的防误报门槛）；`wide` 档用于"只记录"的试跑，看命中与误报再定缺省。`windowChars` 须不小于 `maxPeriodChars × minRepeats`，否则启动时报错。

```json
{
  "truncationContinuation": { "maxPerRun": 3 },
  "repetitionGuard": { "mode": "log", "preset": "wide" }
}
```

## 墙钟预算对模型可见

`pigeon run --wall-clock <毫秒>` 给本次运行设墙钟预算，到点即中止（终态 `wall-clock-limit`）。设了预算时模型看得到预算与剩余时间（决策 418）：

- 开工状态块多一节「Time budget」：总预算、已用与剩余（不到两分钟按秒，否则按整分钟，都向下取整），并说明之后何时更新、run_command 的超时会按剩余时间缩短。
- 之后以追加方式更新这一节，已有的消息一字不改：剩余时间每跌破总预算的 80%、60%、40%、20% 一档追加一次；别的节（git 状态等）有变化要追加时，这一节随之带上当前的已用与剩余；同一档内分钟数的变化不单独追加。这一节在会话记录里按"预算起点与总量 + 档位"记作已发，压缩之后重发的完整块带当前值。
- 剩余低于总预算的 20% 时另追加一节「Time reminder」：优先拿出可交付的结果、不要再启动耗时长的任务。正文固定，只追加一次（压缩之后重发的完整块照常带上）。
- run_command 的超时按剩余时间夹取，见"单次超时与后台作业"。
- 不设预算时以上都不出现，开工状态、状态更新与 run_command 的行为不变；终端界面没有墙钟预算。

### 单次超时与后台作业

run_command 的单次超时缺省 120 秒，模型可用参数 `timeout_seconds` 另设，上限 600 秒（缺省与上限见上表，可改）；给得超过上限按上限执行，结果里注明给的值已夹到上限（决策 411）。设了墙钟预算的运行（见"墙钟预算对模型可见"）里，前台命令的超时（给的或缺省的）超过剩余时间减去 30 秒余量时按后者执行（整秒，至少 1 秒），结果里注明已按剩余时间缩短；与上限夹取叠加时取更小者，只注明起作用的那一种；后台作业不受影响（决策 418）。到时终止整个进程组：本机 Linux/macOS 对整组发 SIGKILL，本机 Windows 杀进程树；容器执行端里命令以 setsid 另起进程组并带一个每次随机的标记环境变量，到时宿主另发一次辅助调用，按标记在容器里找到命令连同它的子孙进程杀掉（组长带标记的整组杀，再逐个杀带标记的），命令后的文件变化照常取到，不再重启容器；中止或超时落在命令开始之前（观测脚本还在取证）时，连观测脚本一起杀掉，命令不会再被起来。

前台命令以输出全部关闭为结束（决策 410，判定与超时行为不变）：命令里放到后台（`&`，Windows 为 `start /b`）又没把输出重定向走的进程会一直占着输出，命令等满时限后连同它被整组终止。工具说明写明：一直运行的进程用后台作业（服务、会话结束后还要用的进程再标 `keep_after_session`，见下），非放到后台不可时先把输出重定向到文件（`命令 > 文件 2>&1 &`，Windows 为 `start /b 命令 > 文件 2>&1`）；本会话不能开后台作业时只写后一种。本机执行端在命令超时的那一刻，若命令本身（直接子进程）已经退出、是它的子孙仍占着输出，超时的报错里另起一行点明这一原因并给出上面的做法；其余超时的报错照旧。容器执行端里，命令本身退出后观测脚本照常取证收尾，子孙占着输出时按辅助调用的限时到点按标记杀掉、按正常结束交回，不算超时，因此不出这一行。

开发服务器、watch、长构建这类命令可带参数 `background: true` 在后台运行：立即交回作业号（j1、j2……），命令在执行端里接着跑，输出持续写进本会话的落盘目录（与上文完整输出同一处，单个文件超过上限只留末尾），作业结束后可用 read_file 按虚拟路径读全文。两件配套工具与 run_command 一同注册：`job_output` 读状态与上次查看之后的新增输出，可带 `wait_seconds`（至多 600）等它结束，不给作业号时等任意一个结束或列出全部作业；`job_kill` 停掉本会话的作业。作业的命令退出时，它放到后台的子孙（`x &`、`nohup`）随作业结束一并停掉（本机 Linux/macOS 按进程组，Windows 按进程树，容器里按组与标记），作业结束后不留进程。`job_output` 是读类工具，可与其他读类工具并行；`job_kill` 串行。两者只看、只停本会话的作业，免审批。

- 审批与钩子同前台命令：后台命令照样经 `PreToolUse`、审批与放权规则；`PostToolUse` 在启动时触发（这时的工具结果是启动回执，没有退出码与输出），作业结束不再触发钩子。
- 后台作业不受单次超时约束，一直跑到结束、被 `job_kill` 停掉或会话结束（标了会话结束后保留的除外，见下）；同时给 `timeout_seconds` 与 `background` 即拒绝。
- 上限：每会话同时在跑的与整次运行同时在跑的各有上限，超出直接拒绝并列出在跑的作业，不排队。
- 结束通知：作业结束时一条通知进模型的下一轮（终端界面里模型空闲时叫醒它；通知是给模型的，消息区不显示，另写一行暗色的简短结果，如 `job j1 ended (exit code 0, took 12s): $ npm test`）；还没递出时又有作业结束的合并成一条；已由 `job_output` 或 `job_kill` 交回结束状态的不再通知。
- 与之后的命令重叠：后台作业与之后的命令同时运行（命令的逐条执行不约束后台作业），可能改同一批文件、占同一个端口。作业结束时以开始与结束的取证比出期间变化，扣除这期间 Pigeon 已知的前台改动（前台命令报出的与写工具改过的文件），注明可能不精确；有作业在跑时，前台命令的变化报告加一句提示；这期间拍的代码快照在会话记录里记下在跑的作业号；容器报内存超限时注明期间在跑的作业。
- `job_output` 不计入打转检测；不带等待时长的连续查询另计，连续 5 次、作业又都没变化即拒绝，请模型带上等待时长或先做别的。
- 终端界面按 Esc 只停当前这一轮，后台作业照跑；要停作业用 `job_kill`，或者结束会话。会话结束（退出终端界面、headless 运行结束或被中止）时停掉本会话全部作业（标了保留的除外）并记下来由。沙箱会话交回前有作业在跑，先提示一行（会话中途 `/export` 时作业照跑，交回的可能是做到一半的样子）。
- 无人值守（`pigeon run`）：一次运行结束后还有作业在跑的，先交一条通知列出在跑的作业，让模型处理一轮（要结果就用 `job_output` 等，不要的用 `job_kill` 停掉）；之后再等剩下的作业，作业结束的通知交给模型跑一轮，直到没有在跑的作业。收尾总时限（`backgroundCloseoutSeconds`）从收尾开始起算、每次运行各自计，计入运行的墙钟预算，墙钟到了照常中止；收尾期间 `job_output` 的等待不超过剩余时限；收尾的每一轮照常计入轮数与 token 上限。总时限到了停掉余下的作业、把通知交给模型跑一轮，此后本次运行拒绝新开作业；总时限为 0 时不交"仍在跑"、不等，直接停掉。运行以出错或中止结束时不进收尾轮，作业随会话结束停掉并记下，终态照旧。
- 会话结束后保留（决策 409）：起服务、守护进程，或判分、使用者在会话结束后还要用到的长时间进程，模型在 `background: true` 之外再给 `keep_after_session: true`（只与 `background` 同用，单给即拒绝）。会话里与普通作业一样：计入同时在跑的上限，可用 `job_output` 查看、`job_kill` 停掉，结束了照常通知；状态句注明"会话结束后保留"。会话收尾（无人值守运行的结束、退出终端界面，含出错、中止与撞上限）时不等它、不停它，也不在"仍在跑"的通知里列出；收尾只等、只停没标保留的作业。会话结束时还在跑的保留作业记一条"保留"（`pigeon.background-job` 条目，`event` 为 `kept`，本机作业带进程号），交出作业池的名额，此后 Pigeon 不再管它；它在会话结束之前自己结束的，照常记结束。续跑时标了保留的作业不算丢失。`pigeon run --json` 的结果多一个字段 `keptJobs`，列出本次运行结束时保留下来的作业：会话号 `sessionId`、作业号 `jobId`、命令 `command`、本机作业的进程号 `pid`；没有即不出这个字段。不带 `--json` 的 `pigeon run` 与终端界面不出文字提示。
  - 免得被清理带走，保留的作业启动时就不进各条清理路径：会话结束时的整组停止（`killAll`）与无人值守收尾都跳过它；不写 `.pigeon/state/jobs/` 下的记录文件，崩溃后下次启动的清理按记录找进程，碰不到它；本机不登记 Pigeon 进程退出时的兜底终止，各平台都分离启动（Linux/macOS 本来就是独立进程组，Windows 不进 Node 的"父进程退出即终止"作业对象）；组长退出后不清扫组里（Windows 为进程树里）的子孙，容器里的包装脚本同样不清扫。会话结束时交出跟踪，Pigeon 进程照常退出、不被它拖住。
  - 输出直接写进落盘目录里的那个文件（进程的标准输出与标准错误是追加打开的文件，不经 Pigeon 的管道），Pigeon 退出后写输出不会碰到断掉的管道；单个文件的大小上限不管保留的作业，不砍前面。会话里 `job_output` 照常读新增的；作业在会话里结束的，全文照常记进落盘索引。
  - 沙箱会话的容器随收尾删除，里面保留的作业随之结束：交回前的提示把它们单列一句（交回时仍在跑，交回的改动可能是做到一半的样子），`pigeon run --sandbox` 的结果里不列 `keptJobs`。
  - Windows 本机：分离启动的进程没有控制台，经 cmd.exe 起的控制台程序可能另开一个控制台窗口。
- 善后：每个在跑的作业在 `.pigeon/state/jobs/` 下有一个记录文件（所属进程号、作业进程号与启动时间、标记，容器作业另记容器名），作业结束即删。Pigeon 异常退出后，下次启动时清理所属进程已不在的记录：本机按进程号找到进程，核对启动时间与标记（Windows 读不到别的进程的环境变量，改核对命令行）一致才杀整个进程组或进程树，不一致即当作进程号已被复用，不动组长、只删记录；不论组长在不在，带着标记的子孙另扫一遍（Linux 扫 /proc，macOS 扫 ps）；查询本身失败（ps、PowerShell 超时等）的记录留着，下次启动再试。容器作业按标记查杀（docker 调用前缀随本会话执行端的配置），容器不可用的记录同样留着。续跑时，会话记录里只有启动、没有结束的作业提示模型已丢失。作业的启动与结束各记一条会话记录（`pigeon trace` 也显示）。

run_command 何时经 shell：命令串按引号规则切成参数数组直接执行；引号外出现管道、重定向、`;` 与 `&` 串联、命令替换（`$(` 与反引号），或引号外的换行（多行命令，与 `;` 同等）时，整条命令原样交给 shell 运行，与其他经 shell 的命令同一套审批（决策 413）。引号内的换行是参数的一部分；命令首尾的空白与换行不因此经 shell。Linux、macOS 与容器执行端经 `/bin/sh -c`，多行命令逐行执行；宿主是 Windows 时容器执行端的命令同样在容器里经 `/bin/sh -c` 运行。本机 Windows 经 `cmd.exe /d /s /c`，而 cmd.exe 只执行第一个换行之前的部分（引号内的换行也一样），因此要经 cmd.exe 运行的命令（去掉首尾空白后）含换行即报错、不执行，提示用 `&&` 连成一行或写成脚本文件再运行；不经 shell 直接执行的命令里引号内的换行照常是参数（决策 415）。

run_command 的命令串按执行端能执行的长度另判：Linux 与容器执行端至多约 124 KiB（UTF-8），Windows 命令行至多约 32000 字符、经 cmd.exe 约 8000 字符；超出时直接报错，建议先用 write_file 写成脚本再运行。

```json
{ "tools": { "readFile": { "maxBytes": 102400 }, "runCommand": { "outputTailBytes": 32768 } } }
```

## 上下文压缩

上下文超过触发点时自动压缩（决策 188、218）：最近约 2 万 token 原样保留，其余由模型写成摘要，作为压缩条目写进会话树，原始消息照留在会话文件里。挂点在一次 Run 内轮与轮之间、一次 Run 开始之前，另有手动 `/compact [重点]`。触发点为模型窗口减预留（16384 token）。

界面上：自动压缩压成了不另写一行（状态栏的上下文用量随之下降，决策 460）；手动 `/compact` 写一行压缩前后的 token 数；没压成（摘要请求失败、没有可摘要的内容等）照报一行。

模型窗口按以下顺序取（决策 422）：

1. 启动参数 `--context-window <n>`（终端界面与 `pigeon run` 都接受；无头运行的 `compaction` 选项同此），来源记为 `explicit`；
2. 本次所用模型的模型信息里的窗口（见上文"模型信息"：设置 `modelInfo.models` 的手填值、接入模块声明、pi-ai 自带目录），来源记为 `settings`、`declared` 或 `catalog`；
3. 都没有时用缺省 1,000,000，来源记为 `default`。

摘要请求有两种发法（决策 424），都经主请求同一个模型接入（同一网关、计量与失败重试），切点、原样保留的部分、压缩条目与之后从会话树还原的上下文两者相同，只是摘要从哪条请求来不同：

- **接续式**（轮间、Run 开始前与手动 `/compact` 的常规做法）：照原样发出这段会话——与下一次主请求同一个模型、系统提示、工具定义与全部消息（已有的上下文裁剪照样应用；压缩之前刚做的那次裁剪不算，消息与上一次主请求一致），选项同主请求（思考档位、温度等），末尾追加一条摘要指令。请求的前缀与上一次主请求逐字节相同，服务方的前缀缓存命中，花费主要是指令与摘要输出。指令要求的摘要结构与该保留的内容同上游 pi 的摘要提示词（目标、约束、进度、关键决定、下一步、关键上下文；原样保留文件路径、函数名与报错），并写明只写摘要、不续对话、不调用工具；请求不带 `toolChoice`：实测带 `none` 时服务方把工具定义从提示里拿掉，前缀对不上、缓存全不命中，所以"不调用工具"只由指令约束，回复里出现工具调用即作废、改走独立式。思考档位不改，免得服务方因思考设置不同而换一种方式组织历史、前缀对不上；开思考时实际请求的输出上限照上文"推理档位（思考）"的规则另加思考预算，思考与摘要共用它（服务方按剩余上下文收窄）。只取一条回复。切点落在一轮中间时，与上游相同地另写那一轮的摘要（原始请求、早先进展、理解保留部分所需的上下文），指令里引出那一轮开头的一句话以指明是哪一轮；之前有历史时同一条回复里先写历史摘要、再以上游的分隔接上那一轮的摘要（上游是两次请求），之前没有历史时照上游以"No prior history."开头。
- **独立式**（上游 pi 的做法）：把待摘要的部分另组成一条请求、配专门的摘要系统提示，不请求思考，温度照设置。用在：因上下文超长出错而触发的压缩（整段会话已放不下）；整段放不下——这段会话此刻的 token 数（与压缩判定同一口径的估算）加摘要指令（按字符估算）加摘要的输出上限超过模型窗口；接续式没拿到可用的摘要——请求出错（含被服务方拒收或超长）、回复里有工具调用或没有文字——此时改走一次独立式（被中断的不改走）。

摘要的输出上限两种发法相同：0.8 倍预留与模型输出上限的较小者（缺省 13107 token）。触发点取缺省（窗口减预留）时，压缩时剩下的空间不到预留量，一轮多出来的内容稍多就放不下摘要的输出上限，多走独立式；触发点调低到离窗口较远时一般都放得下，走接续式。会话记录里压缩条目照旧写摘要、原样保留的部分与压缩前的 token 数，`details.summaryRequest` 另记这次的发法：`{ "mode": "continuation" }` 或 `{ "mode": "standalone", "reason": … }`（`overflow` 超长触发、`no-room` 放不下、`failed` 接续式请求出错、`tool-call` 回复里有工具调用、`empty` 回复没有文字、`no-conversation` 没有会话可接）。

`--compact-threshold <n>` 给出触发点（须小于窗口），`--compact-keep <n>` 给出原样保留的量。窗口须大于预留，否则启动时报错，报错里写明窗口的来源。每个 Run 开始条目的 `compaction` 记下所用的窗口与来源（`contextWindowSource`）、预留、保留量与触发点；终端界面状态栏的上下文用量按这个窗口算。

模型请求因上下文超长出错时（决策 422），先压缩再重试这次请求一次。是否为上下文超长由 pi-ai 的识别函数 `isContextOverflow` 按服务方的报错文案判定（限额类报错先排除），Pigeon 不另加判断。压缩走自动压缩的同一流程：压缩前回调与 `PreCompact` 钩子（记 auto）、压缩条目写进会话记录（压成了界面不另写；无头运行照旧在运行期告警里提示一行）；压成了即以压缩后的上下文接着跑，开工状态块照压缩之后重发完整块，出错的那条回复照实留在会话记录里、不再发给模型。压缩没压成（摘要请求失败、没有可摘要的内容、会话文件不可用）时不重试，按原错误收尾，Run 收尾条目的 `overflowCompaction` 记下没压成的阶段与错误文本或跳过的原因。同一次超长只重试一次：重试的那次请求仍超长即按原错误收尾；重试之后有过正常回复，之后再超长算新的一次。请求以 HTTP 400 出错、且请求里有上次成功回复之后新加的图时，先按"请求仍被服务方拒收"处理（见下文"读档工具：图片与二进制文件"）。

## 上下文裁剪

`contextPrune` 一节控制缓存感知的上下文裁剪（决策 361，按时机分候选见决策 373），缺省开启。裁剪把最近几轮之外的部分工具结果换成一段固定格式的占位，写明原来是什么（工具、读的文件与行、命令、搜索词、大小、为什么裁）与找回方式（重新读取、命令输出的虚拟路径、重新搜索或调用）。只换工具结果的正文，工具调用号与工具名留着，调用与结果的配对不变；用户的话、模型正文、工具调用参数、思考内容、开工状态块与变化通道的消息一律不碰。原文照旧在会话记录里，压缩摘要与打转检测看的都是原文。

候选是保护轮之外、还没裁过的三类工具结果：被后来的读取覆盖（同一文件、覆盖它全部行；图片与其他二进制文件按整个文件读，之后再读同一文件即覆盖）或被 write_file 整体覆写的过时读取；无事发生的结果（零命中的 grep、glob、search_sessions，没有结果也没有答案的 web_search，退出码 0 且没有输出也没有文件变化的 run_command）；不小于最小大小的较大旧结果。占位比原文还大的不算。run_command 的输出截断了而全文没落盘的不裁：上下文里的开头与末尾是唯一副本，命令可能有副作用，不能指望重新运行。

什么时候裁：

- 免费时机，一次裁光全部三类候选（含较大的旧结果）：自动压缩之前（先裁，按裁后的上下文重估，降到触发点以下即不再摘要，仍超过才摘要；手动 `/compact` 不先裁）；Run 开始时模型、广告的工具集或系统提示与上一个 Run 不同（续跑与 `/reload` 时同会话记录或旧运行面比；开工状态块的变化不算）；空闲超过缓存保留时长。
- 其余每次请求之前是付费时机，候选只有过时读取，无事发生的结果随批顺带；较大的旧结果不在付费时机裁（它们多是仍在用的文件，裁掉后常被读回，读回按未命中价计）。按价格比算账：在候选中选改写起点使预计净省最大，满足 裁掉量 × N ≥（价格比 − 1）× 改写点之后的量，且裁掉量不小于最小批量才裁。无事发生的结果不当改写起点，也不计入这两个条件。token 量按与压缩判定同一口径的估算。

另有图片预算（决策 414）：历史里的图片每次请求都会重发，合计超过服务方的请求体上限请求就发不出去。没裁的工具结果里的图片（按 base64 字节数）合计超过 `maxImageBytes` 时，不论时机、不受保护轮与价格比约束，从最旧的起把带图的工具结果换成占位（写明读的是哪张图、类型与像素尺寸，需要时重新读取），直到合计不超过预算的一半；最新一个带图的结果与最近一轮的结果（模型还没看过）不清。这类裁剪记作时机 `images`、原因 `image`。压缩时摘要请求只带文字，压缩掉的那段里的图片随之移出上下文。

价格比是重写价与命中价之比，取值顺序：设置里的 `priceRatio`；缓存规则写明该服务方不做缓存时按 1；模型信息的价格（重写价取未命中价与写缓存价中较高者，除以命中价；给了 `writeMultiplier` 时写缓存价按未命中价乘它算）；缓存规则里的写入、读取倍率；都取不到时按 50（价差很大，从严）。保留时长取设置里的 `retentionSeconds`，否则取缓存规则较短一档的秒数，取不到即不按空闲裁。

每次裁剪在会话记录里写一条 `pigeon.prune` 条目：裁了哪些（工具调用号、工具名、原因、原来的 token 数、换成的占位原文）、时机、价格比与 N、裁掉量与改写点之后的量、估算的代价与节省（按命中价折算的 token 当量，免费时机代价记 0）、前后的上下文 token 数。记录先写进会话、再生效（写不成这次就不裁）；组装请求时按记录应用，新裁出错时只应用已有的裁剪；续跑、续做、分叉与 `/reload` 照记录重放，前缀逐字节一致（决策 373 之前在付费时机裁掉较大旧结果的记录也照样重放）。裁掉的命令输出还没落盘的（没超长的非空输出）先补落盘，补不成的不裁；占位给出 `pigeon://outputs/<会话号>/<编号>`（只存了前一部分的照实写明），命令带文件变化的保留文件变化清单，只换掉输出部分。落盘总量满了按上限清理掉的输出，读取时明确报已被清理，需要时重新运行；裁掉的读取在上下文里再没有同一文件没裁的读写结果时，不再算本会话读过（之后覆盖这个文件须重新读取）。

| `contextPrune.maxImageBytes` | 上下文里没裁的图片（base64）合计至多这么多字节，超过即从最旧的起清掉带图的结果，清到一半以下 | 8388608（8 MiB） |

```json
{ "contextPrune": { "protectTurns": 8, "priceRatio": 10 } }
```

## 快照不收的大文件

Pigeon 拍的工作目录快照——沙箱的起点、检查点与退出快照，以及取回面板会话的改动时给它的工作树写的树——收已跟踪文件的当前内容与未跟踪且未被忽略的文件（决策 381）。其中未跟踪的文件有上限：单个超过 `untrackedFileMaxBytes` 的不收；其余合计超过 `untrackedTotalMaxBytes` 时从大到小继续不收，直到不超过上限。已跟踪的文件不受限，照常收。只算普通文件，符号链接与嵌套仓库不算；未跟踪与否按你的暂存区判定，找文件用 Pigeon 加固过的 git（不跑过滤、钩子与 fsmonitor）。

| 键 | 含义 | 缺省 |
| --- | --- | --- |
| `snapshot.untrackedFileMaxBytes` | 单个未跟踪文件超过这么多字节即不收 | 10485760（10 MiB） |
| `snapshot.untrackedTotalMaxBytes` | 收进快照的未跟踪文件合计至多这么多字节 | 209715200（200 MiB） |

没收的文件列出路径与大小：

- 沙箱开工：写进开工状态块的环境一节，模型知道工作区里少了哪些文件；沙箱开工时另在终端列出。
- 检查点与退出快照：记在代码快照条目里。快照只用于分叉（在独立工作树里续跑）与复盘读取，不回写主工作目录，没收的文件在主工作目录里原样不动；从检查点分叉出的工作树里没有它们。

```json
{ "snapshot": { "untrackedFileMaxBytes": 52428800 } }
```

## key 走环境变量

设置文件里没有任何 key 字段。智谱搜索的 key 从环境变量 `ZAI_API_KEY` 读，Tavily 的从 `TAVILY_API_KEY` 读，DeepSeek 用模型接入同一个环境变量。在 `web` 一节里写了 `apiKey` 即报错，并给出应设的环境变量名。

自带的 DeepSeek 模型接入另读环境变量 `DEEPSEEK_BASE_URL`：给了就用它作 Anthropic 兼容端点的根（请求照旧发到 `<根>/v1/messages`），没给或为空时用官方地址；它须为 http 或 https 地址，否则启动时报错（报错里带上该地址，不带 key）。`web_search` 的 DeepSeek 后端在设置里显式给了 `web.search.deepseek.baseUrl` 时以设置为准，没给时同样跟这个环境变量。

## 程序状态目录 `.pigeon/state/`

程序写的东西都在 `.pigeon/state/` 下：会话（`sessions/`）、命令输出的落盘（`outputs/`）、在跑后台作业的记录（`jobs/`）、项目级学到的记忆（`memory.md` 与 `memory.lock`）、`/fork` 等留下的工作树（`worktrees/`）、终端界面的输入历史（`tui-history.json`）与日志（`logs/`）。用户级的程序状态（用户级学到的记忆 `memory.md`、配置确认记录 `config-trust.json`、迁移备份 `migration-backup/`）在 `~/.pigeon/state/`。

会话文件（决策 432）：终端界面新开的会话，等第一次真要落盘的写入（发出消息、记授权等）才建会话文件并取锁；在此之前只有钩子运行记录（如会话开始的钩子）时先留在内存里，建文件时按原顺序补写，没发过消息就退出则不留会话文件（钩子照常执行）。续跑与分支会话照旧立即打开或建立；`pigeon run` 带着任务开跑，不受影响。只有文件头与钩子运行记录的会话（以前启动即建文件时留下的）不列入 `pigeon session list`。

人写的内容：`.pigeon/skills`、`~/.pigeon/skills` 留在原处；人写的说明改读 AGENTS.md（见下文"记忆与人写的说明"），旧的 `.pigeon/memory/` 与 `~/.pigeon/preferences.md` 不再读取，由迁移命令处理。

启动时不建 `.pigeon/state/`：打开终端界面、不发消息就退出（只敲了斜杠命令也一样），项目里不留 `.pigeon`。`.pigeon/state/` 在第一次真要写程序状态时才建——第一条消息建会话文件、`pigeon run` 开跑、`/search` 写检索缓存、项目级记忆的写入与编辑、`/grants save` 写个人设置等。斜杠命令在程序状态目录还没有时不记进跨启动的输入历史（本次启动内仍可用 ↑ 翻到）。

忽略规则写在使用者的全局 git 排除文件里，不再写 `.pigeon/.gitignore`（以前写下的不动，快照与沙箱交回照旧认得它）。在 git 仓库里第一次建程序状态或写 `settings.local.json` 时，若 `.pigeon/state/`、`.pigeon/settings.local.json`、`.pigeon/wt/` 尚未被忽略，把下面缺的行追加进全局排除文件（位置见下一段），已有的行不重复；写进去不另行告知：

```gitignore
**/.pigeon/state/
**/.pigeon/settings.local.json
**/.pigeon/wt/
```

全局排除文件的位置与 git 实际读的一致：用户级 git 配置（连同其中 include 进来的配置）设了 `core.excludesFile` 时用它（`~` 按 `HOME` 展开）；没设时用 `$XDG_CONFIG_HOME/git/ignore`，没设 `XDG_CONFIG_HOME` 时用 `$HOME/.config/git/ignore`。`core.excludesFile` 设成相对路径时位置不明，Pigeon 不写，只提示一行请你自行加入。写一次即覆盖本机所有仓库、工作树与新克隆；写完会再核一遍 git 是否确实忽略了，没生效同样提示。非 git 目录不写任何忽略规则。写不进时只提示一行（附上要加的三行），不影响运行。不想让 Pigeon 改全局排除文件的，事先自己在项目的 `.gitignore` 或全局排除文件里忽略这三处即可（已被忽略就不会再写）。

`pigeon run --governance-root <目录>` 把治理根与工作区根分开：设置三层、项目 `.mcp.json` 与程序状态（`.pigeon/state/` 全部内容，含会话与检索缓存）锚到治理根，工作区只是 agent 干活的代码——工作区自带的 `.pigeon/` 设置与 `.mcp.json` 不生效，程序状态也不落进工作区。缺省与 `--root` 相同（行为不变）；不与 `--sandbox` 同用。

快照、checkpoint 与改动叠回只排除 `.pigeon/state`、`.pigeon/settings.local.json` 与独立工作树所在的 `.pigeon/wt`；仓库已跟踪的 `.pigeon/settings.json` 与 `.pigeon/skills` 是项目内容，照常进快照与叠加。列目录与命令的文件变化报告仍不列整个 `.pigeon`。命令的文件变化在 git 工作区里按命令前后两次 git status 找候选，被 `.gitignore` 忽略的文件不报；非 git 工作区比全量清单，跳过依赖、虚拟环境、构建产物与缓存目录（`node_modules`、`.venv`、`venv`、`dist`、`build`、`target`、`__pycache__`、`.next`、`coverage` 等）。Pigeon 自己在后台起的 git（文件变化的取证、代码快照、退出快照等）不执行仓库里配置的过滤（clean、smudge、process）、钩子与 fsmonitor——这些命令可能指向工作区里写工具改得到的脚本；写工具也一律不写 `.git`。影响：文件变化报告照常；用 LFS 一类过滤的仓库里，快照存进大文件的真实内容而不是指针，本地对象库会变大。

## 留下的工作树

`/fork` 的分支在 `.pigeon/state/worktrees/<会话号>-fork` 一类的 git 工作树里续跑，分支为 `pigeon/fork-<会话号后 8 位>`；以前版本的 worker 也在这里留下过工作树与 `pigeon/` 分支（决策 457 删除 worker 之后不再新建）。这些工作树不按天数自动删除，用 `/worktrees`（终端界面）或 `pigeon worktrees list` 列出与清理：

- 列出要在主检出里执行（在这些工作树里执行即拒绝）：`.pigeon/state/worktrees/` 下的工作树、目录已不在而 git 仍登记的、没有工作树的 `pigeon/` 分支（含以前旧命名留下的）、git 已不认的残留目录，以及独立工作树（见下节）。每项给出所属会话（读该会话文件头里的父会话）、有无未取走的改动（相对起点改过、内容又与主检出不同的文件数；只剩分支的看分支上有无新提交）与占用大小，旧命名的标出。起点取分支建立时的那条引用日志；取不到记为"不明"，按有改动对待。
- 删除：`/worktrees clean` 或 `pigeon worktrees clean` 不带编号只删没有未取走改动的；带编号或名字删点名的；`--all` 连有改动的一起删；名字对应多项时不删，须给编号或完整分支名。删除前先列出将删的各项，有未取走改动的写明"删除后丢失"：终端界面里输入 `/worktrees confirm` 才删（期间输入别的 `/worktrees` 命令即作罢）；命令行在终端里问一次 `[y/N]`，没有终端时须加 `--yes`。确认之后、真删之前再核一遍，期间变成在用或改动有变化的不删并说明。在用的一律不删：工作树里的会话被一个仍在的进程打开（锁文件读不了也算）、所属会话正被另一个仍在的进程打开、刚建还没有会话记录（10 分钟内）。
- 删除不跟随链接：工作树里的符号链接与目录联接（例如指向外部的 `node_modules`）只删链接本身，指向的目录不碰；git 的登记只删这一个工作树的，被 `git worktree lock` 锁定的不删。删除失败（例如 Windows 上文件被占用）时工作树留着。

被 git 忽略的本地文件（`.env` 之类）不在检出里。在项目根放一个 `.worktreeinclude`，按 `.gitignore` 的写法列出要带进工作树的文件，建工作树时（`/fork`、独立工作树、会话面板派出的会话）把主工作目录里既匹配其中规则、又被 git 忽略的文件复制进去；已跟踪的文件本就在检出里，不重复复制，未被忽略的文件不复制，`.pigeon` 下的一律不复制。`.worktreeinclude` 放在仓库顶层，路径相对仓库顶层（会话开在子目录里也一样）。只复制普通文件；来源路径上任何一段是符号链接或目录联接的不复制（不会经链接复制到工作区之外的文件），目标路径上有链接的也不复制，工作树里已有的不覆盖。清单在建工作树之前算好，复制出错即删掉刚建的工作树与分支。依赖目录不做链接，按需安装；列进 `.worktreeinclude` 的目录会整个复制，文件个数不设上限（清单本身以 256 MiB 为限），很大的目录会让每次建工作树都变慢。没有 `.worktreeinclude` 即不复制。例：

```gitignore
.env
.env.local
config/secrets.json
```

## 独立工作树

`pigeon --worktree <名字>`（也可写 `--worktree=<名字>`）在 `<主仓库根>/.pigeon/wt/<名字>` 的 git 工作树里开终端界面的会话，分支为 `pigeon-wt/<名字>`。名字只能用小写字母、数字、下划线与连字符，字母或数字开头，最长 64。只有终端界面支持；不与 `--sandbox`、`--continue`、`--resume` 同用（续接开在工作树里的会话时会自动回到那个工作树）。不在 git 仓库里时报错。

- 新建时的起点：缺省为远端默认分支（`origin/HEAD` 指向的分支）的最新版——远端引用超过 24 小时没取过就先 `git fetch` 一次，限时约 5 秒，不弹任何交互（不问密码；没有自己指定 ssh——`GIT_SSH_COMMAND`、`GIT_SSH` 与 git 配置 `core.sshCommand` 都没设——时 ssh 以批处理方式）；没有远端默认分支、取不到或超时就用当前 HEAD，并在会话里报一行写明起点用了 HEAD 与原因。设置 `worktree.baseRef` 为 `"head"` 时直接用当前 HEAD。按 `.worktreeinclude` 复制被忽略的本地文件（见上文"留下的工作树"），并确保全局排除文件里有 `**/.pigeon/wt/`（见上文"程序状态目录"）。建立时把起点提交记在仓库配置的 `branch.pigeon-wt/<名字>.pigeonBase`（删分支时随之删掉）；之后判断有没有新提交按它，记录不在即按"起点不明"处理。
- 同名的工作树已在就直接打开，不重建；同名目录在却不是本仓库的工作树即报错。
- 会话记录、设置与记忆仍在主仓库根的 `.pigeon`（与主检出里的会话在同一处，`/resume` 看得到），代码改动在工作树里。
- 退出时：另有仍在的进程开着这个工作树（`--worktree` 或 `enter_worktree` 进入的会话，不论有没有会话文件）就保留不删并说明；否则工作树没有改动（没有未提交的改动与未跟踪文件、仍在 `pigeon-wt/<名字>` 上、HEAD 与分支仍指向记下的起点）就删掉工作树与分支；有改动、起点不明或工作树已换到别的分支上，就在终端里问一句：`k` 保留（打印下次进入的命令 `pigeon --worktree <名字>`）或 `d` 删除（工作树里的改动与 `pigeon-wt/<名字>` 上的提交都会丢失）；没有终端可问时保留。删除只删 `pigeon-wt/<名字>` 这一个分支，工作树换到的别的分支不动。
- `/worktrees` 与 `pigeon worktrees list` 也列出独立工作树（标明"独立工作树"），`clean` 不带编号与 `--all` 都不挑它们，点名才删（同样不跟随链接，只删 `pigeon-wt/<名字>` 分支）。有仍在的进程开着它时算在用、不删（会话开在独立工作树里的期间，进程在用户级程序状态目录的 `worktree-use/` 下持有一个标记，进程退出即释放，崩溃留下的在下次检查时按进程已不在清掉）。工作树已换到别的分支上的，未取走的改动记为"不明"。
- 独立工作树放在 `.pigeon/wt/` 而不是 `.pigeon/worktrees/`：后者是更早版本的工作树位置，启动检查与迁移命令按"目录在即旧布局"处理它（迁移命令把其中旧的工作树挪进 `.pigeon/state/worktrees/`）。

模型也能在会话中途建工作树并把会话移进去（工具 `enter_worktree`，参照 Claude Code 的 EnterWorktree）：只给终端界面里启动与 `/resume` 打开的会话注册（面板派出的会话不带）（`pigeon run`、沙箱都没有），工作区不是 git 仓库时不注册；工具说明与系统提示都写明只在你明确要求"在工作树里做"时才用。它按写操作审批（建目录与分支），与 `--worktree` 同一套建立、起点与 `.worktreeinclude` 复制。移动发生在这一轮结束时：终端界面按 `/reload` 的先建后换重建运行面（同一会话文件、同一放权，系统提示不变），工作区换成工作树，然后自动递一条通知让 agent 接着做；消息区写一行移进了哪个工作树（分支），主检出里未提交的改动不会带进工作树，有几个没带过去写在同一行（工具结果里同样写明）。移动成功之后会话里记一条 `pigeon.worktree` 条目，续接、`/resume`、`/reload` 都按主分支上最后一条回到工作树（工作树已删就回到主检出）；`/resume` 换到开在主检出里的会话时，消息区写一行离开了哪个工作树（工作树保留，改动在那里）；要回去用 `pigeon --worktree <名字>`。退出时的清理与 `--worktree` 相同。以下情况不移：已在工作树里（再调即拒绝）；同一轮里已调过一次（再调即拒绝）；这一轮被 Esc 中止；重建运行面失败。不移时工作树留着，消息区与递给模型的通知都写明原因，会话留在原处，不自动开下一轮。

## 终端界面

终端界面用全屏（备用屏）：消息区占满上方，输入框、状态行与状态栏固定在底部；对话再长也不会把输入框挤走。界面里的文字只有三类：出错且不看就不知道的报错、你点名要的结果、需要你当场决定的；功能说明都在本文档里（决策 460）。状态行紧贴在输入框上沿（上方隔一行空白；会话列表、审批区打开时排在状态行之上），各视图相同。

- 欢迎头（决策 451）：启动时消息区最上方是一只像素鸽子，右边三行字：`Pigeon v版本`、所用模型、当前目录（主目录写作 `~`）。它随消息往上滚，不常驻；会话回退清空消息区后仍在最上方。终端太窄、鸽子与文字并排放不下模型名时只显示文字（过长的按宽度截断，不折行）。鸽子 11 列 × 4 行，用终端缺省的前景色，由四分块字符画成；把这类字符按两格宽显示的终端里会错位。
- 顶部没有标题行（决策 460）：主视图不显示会话名与会话号（当前会话的名字在会话面板的卡片上可见；`/rename` 改名，改成了在消息区写一行暗色的 `renamed to <名字>`）。进入面板会话时，顶上有一行暗色的说明，只写在哪、怎么回去：`session <名字> · esc to go back to the panel`。
- 状态行只写状态词：`running`、`cancelling`（按 Esc 之后等这一轮收尾）、`resuming`；空闲与审批挂着时不写字。会话面板上写会话数与在等回应的数（如 `panel: 3 sessions, 1 waiting`）；进入的子 agent 写它的名字与状态。
- 审批（决策 467、472）：挂着时整块显示在底部的审批区（主视图里在输入框上方，其他视图里在状态行之上；不是浮层，不进消息流），按键先归它。审批区画一个圆角边框（暗色）：第一行是工具名（加粗），接着是要批的那件事本身（`run_command` 的命令、改文件的路径、联网的网站，正常色）与警示（受保护路径、工作区外，正常色）；来源、其余参数（`args: …`）与细节（`argv`、`cwd` 等）一律暗色；改动预览的增行绿、删行红；最后是按键行，按键字母正常色、说明暗色。已经专门显示过的字段（命令、路径）不在参数里重复，`run_command` 预览里重复命令的那行也去掉；原始参数里有、专门显示没覆盖的照旧列出，不藏东西；内容一律先经 036 净化。框线用的是圆角与横竖线字符，把这类字符按两格宽显示的终端里会错位。审批区的高度上限按窗口高度取，内容太长（改动预览等）时留开头与末尾的按键行，中间写明省略了几行，输入框与状态行不会被挤掉。答完审批区即收起，消息流里只留一行暗色的结论，按宽度截断，例如 `✓ approved run_command: npm test`、`✓ allowed for this session: run_command npm test`、`✗ rejected write_file: a.txt (理由)`；面板会话的请求在前面标来源（`[s2] …`）。完整内容在会话记录里，`pigeon trace` 可查；回看历史时审批只显示那一行结论，不还原整块。
- 状态栏（决策 468、469、487）：输入框下方一行，写当前会话的审批模式、上下文用量与本会话累计的 token 数，例如 `auto · ctx 23% (46k/200k) · 1.2M tokens`，窄时 `auto · ctx 23% · 1.2M`。审批模式 `ask`（询问，暗色）或 `auto`（放手，醒目颜色；内部值与会话记录里仍是 `yolo`，`pigeon trace` 照写 `yolo`）；token 数是本会话累计用量（每次请求的输入含缓存读写与输出之和，含本会话的复盘），续接后接着累计；没有上下文窗口信息时只写 token 数。不写模型名（在欢迎头里）与花费（花费只对按量计费的 key 有意义；会话记录里的用量照旧记，`pigeon trace` 可查）。`pigeon trace` 与 `pigeon session list` 同样只写 token 数、不写金额（决策 476）：trace 每轮写输入、输出、缓存读写各多少与这一轮合计（如 `| 1.2k tokens`），session list 每行写会话合计（如 `12k tokens`），写法与状态栏相同。
- 审批模式（决策 469）：`Shift+Tab` 在询问与放手之间切换，当场生效，只对当前会话，之后的工具调用按新模式判定；已经挂着的审批照旧要答（挂着时按键归审批，`Shift+Tab` 不切换）。每次切换在会话记录里记一条（时刻、从什么到什么），`pigeon trace` 可见；续接（重新启动程序）时模式按启动参数定（`--yolo`；沙箱缺省放手，`--sandbox-approval prompt` 改回询问），不沿用记录里最后的模式。`/reload`、换进工作树、`/resume` 换会话都沿用当前模式。面板派出的会话沿用派出时当前会话的模式，之后各切各的；会话在当前与面板之间换手时带着自己的模式。切换不改审批规则：受保护路径等硬性规则在放手模式下照旧；`run_command` 的说明文字与写工具能否写工作区外按开会话时的模式。
- 模型名（决策 453）：欢迎头里写作"模型 id · 服务商"，例如 `deepseek-flash · deepseek`，取运行面的模型信息：接入模块声明了模型（见下文"模型信息"）即用它，否则用启动参数 `--provider`、`--model`；两者都没给（只有占位的 `custom`）时不显示模型。
- 收尾行（决策 452）：一次工作（从发出消息到 agent 干完，含收尾钩子拦下后接着跑的各轮，以及刚收尾就由通知接着跑的一轮，例如换进工作树后自动续上的那轮）结束时，消息区落一行：正常为 `done · 1m 23s`；按 Esc 打断为 `interrupted · 12s`；请求出错为 `error · 45s · 原因`（原因只取第一行）；续跑到上限仍被截断为 `stopped: output limit · 2m 3s`；被打转检测叫停为 `stopped: looping`。不再逐轮显示轮次标记，也不显示失败分类（分类照样记在会话记录里，`pigeon trace` 可查）。`/resume` 回看历史时每次运行各一行，用时取那次运行的开始与收尾时刻。
- 次要信息（决策 454）统一用暗色显示：思考内容、输入框上方的状态行与下方的状态栏、补全列表里命令的参数与说明、会话列表与设置视图的提示和说明、欢迎头里的模型与目录、收尾行、消息区里的工具调用条目（调用行与结果预览；调用失败的只把开头的 `$` 换成红色 `✗`，整行仍暗，回看历史同样），以及消息区里程序写的提示行。真正的报错（请求出错、写入失败、钩子出错、改不成设置等）、要作答的审批块与运行期告警照常醒目，不变暗。
- 滚动与查找：鼠标滚轮滚动消息区；PageUp/PageDown 翻页，Ctrl+Home/Ctrl+End 回到最早/最新（Home/End 留给输入框，移到行首行尾）；Ctrl+Shift+F 或 F3 打开查找（Windows Terminal 缺省占用 Ctrl+Shift+F，可用 F3），Enter/Ctrl+G 下一个，Shift+Enter/Ctrl+Shift+G 上一个，Esc 关。
- 复制与粘贴：用鼠标拖选，松开即复制（写 OSC 52，终端支持即进剪贴板）；有选区时按 Ctrl+C 也是复制（复制后选区清掉，下一次 Ctrl+C 照常清输入），不算退出的第一下。Windows 上右键粘贴剪贴板里的文字（审批或消息面板挂着时不粘贴）。程序接管了鼠标，终端自己的选取暂时用不了。
- 退出：离开全屏，把这次的对话（消息区，行尾不补空格）完整打印到普通屏幕，留在终端的回滚里；打开外部编辑器（例如 `/memory edit`）暂离全屏时不打印。程序异常退出（未捕获的错误）时同样把终端复位：离开全屏、关掉鼠标上报、恢复自动换行与光标。
- 模型的回复按 Markdown 显示：标题、粗体、列表、代码块、引用照样排，标记符号不露出；引用边与分隔线只用 ASCII；`$…$` 不当公式。Markdown 链接的文字与网址不同时，文字后面另外显示网址。网址与绝对路径在支持超链接的终端里成为链接（OSC 8），点了用系统缺省方式打开（只开 http、https 与 file）。工具结果里的图片（只认 png、jpeg、gif、webp）在能显示图片的终端里显示，不能的（例如 Windows Terminal）显示一行文字占位。
- 等模型回复时，状态行上方有一个转圈（ASCII 帧，不带文字），第一段输出到来即收起。
- 运行中输入的话进队列，显示在输入框上方（`queued: …`），空闲后逐条发出（一条跑完再发下一条，不合并）；Alt+Up（Windows 下另认 Alt+Q）把排队内容全部退回输入框修改；按 Esc 中断时排队内容同样退回输入框。
- 斜杠命令：行首打 `/` 列出全部命令（这就是命令清单）；敲了不认识的命令只回一句 `unknown command: /<命令>`。运行中只能用查看类命令、`/quit`、`/resume`、`/new` 等，改当前会话状态或工作目录的命令运行中不能用。命令分两类（决策 484）：管整个程序的（`/quit`、`/config`、`/reload`、`/panel`、`/memory`、`/memory edit`、`/worktrees`）与作用于当前会话的（其余，如 `/compact`、`/resume`、`/new`、`/grants`、`/revoke`、`/fork`、`/take`、`/tasks`、`/hooks`、`/rewind`、`/rename`、`/export`）。`/config` 改值与 `/reload` 对所有会话生效：当前会话马上重建，面板里空闲的马上重建，在跑的这一轮跑完后重建（它的子 agent 还在干活时等它们停下）；别的项目的会话各按自己项目重读，有新的没确认过的条目同样在审批的位置确认（决策 485）。终端界面没有 `/sessions`：看会话、切会话用 `/resume` 的会话列表；命令行的 `pigeon session list` 列出本项目的会话，每行带会话名（没改过名的显示缺省名：工作目录名加会话号末 4 位），可按工具、失败分类与创建时间筛选。
- Ctrl+C 清空输入，连按两下退出：第一下之后状态行临时显示 `press Ctrl+C again to exit`（不写进消息区）。审批时按 `[r]` 写理由，提示也在状态行（`reason for rejecting (enter to send, esc to go back)`），答完消息区只留一行结论。
- 启动时（全屏之前）出的错——MCP 服务起不来、钩子出错、`--worktree` 取远端默认分支失败、沙箱开箱时的告警——在会话的消息区里醒目显示；拉镜像、建镜像这类等待中的进度照旧在进入全屏之前写在终端上。
- 给模型的文字不显示在消息区（决策 460）：打转检测的第 1、2 次提醒、后台作业的结束通知（另写一行简短结果，见后台作业一节）都只进模型的上下文（会话记录里照留）。打转检测叫停时消息区写一行（重复的调用），会话照常可用，想让它接着做直接说"继续"。
- 输入框补全：行首打 `/` 列出命令，方向键选、Tab 或回车套用；打了半截的路径按 Tab 补全（以工作区为根；输入框空时 Tab 什么都不做）；`@` 后跟文件名补全工作区里的文件路径（需要本机有 `fd` 程序，没有即不出结果）。补全只改输入框里的文字，`@路径` 发出时原样作为文字，不会自动附上文件内容。补全列表开着时 Esc 只关列表。路径补全由 pi-tui 做：也会列出工作区之外的路径（`~/`、`/`、`../` 开头的），`@` 的文件搜索会跟随目录链接；很大的目录列得慢。
- `/resume` 换会话时（决策 484），原来的当前会话若还在干活（这一轮没完，或还有子 agent 在干活，含停着但后台作业没收尾的）就退到会话面板成一张卡接着跑，排着的输入一并带过去；闲着的直接关掉，不进面板。`/new` 开一个新会话（决策 488，不带参数）：工作区与治理根跟当前会话所在的项目，沿用当前的审批模式，会话文件等第一次真要落盘时才建；原来的当前会话若还在干活，照上面同一套退到面板接着跑，闲着的直接关掉。`/resume` 不带会话号（以及启动时 `pigeon --resume` 不带会话号）打开整屏的续接视图（决策 471；同设置视图的做法）：方向键选，回车续接选中的会话并回到主视图，Esc 回主视图。每行写最近活动的相对时间（`just now`、`5m ago`、`3h ago`、`2d ago`，超过约一个月写日期）、会话名、git 分支、轮数（沙箱会话另标 `[sandbox]`）与首条输入（决策 473）；分支是会话最后活动时所在的分支（会话在 Run 开始与写档、命令之后记下，变了才记一条；分离头指针时写短提交号；非 git 目录与这之前的旧会话没有即不写）；窗口窄时先截首条输入，留不下了再省掉分支。选中一行按 `Ctrl+R`（动作 `pigeon.resume.rename`，可改）就地改名（决策 474）：名字那一栏变成输入框、预填现名，Enter 保存、Esc 取消；名字规则同 `/rename`，不合规时写明原因、不写；会话正被别的 Pigeon 进程开着（会话锁在别处）时不改、写明是哪个进程。当前会话与面板里开着的会话不在这个列表里（改它们用 `/rename`）。打字即筛选（决策 466）：列表打开后直接打字，按会话内容筛（同会话检索的那一套，只搜对话正文，范围同列表：本工作区可续接的主会话），按相关度排，每行后面接一段命中片段（暗色、按宽度截断）；打字停下约 150 毫秒才检索；Backspace 删字，筛选词为空时恢复全列表；Esc 先清空筛选词，再按才退出。终端界面没有 `/search` 命令：想找以前的事直接问 agent（它有会话检索的三件工具）。列表按当前窗口高度放得下的行数显示（窗口变了即跟着变，选中项不变），随选中项滚动。

### 设置视图 `/config`

`/config` 打开整屏的设置视图（决策 464、465；和会话面板、会话回退同一种做法，不是浮层），Esc 回主视图。设置分组列出，←/→ 或 Tab 切组：

| 组 | 放了哪些 |
|---|---|
| model | `thinking.level`、`modelRequest.maxRetries` |
| web | `web.enabled`、`web.search.backend`、`web.search.maxResults`、`web.search.timeoutMs`、`web.fetch.timeoutMs`、`web.fetch.maxBytes`、`web.fetch.maxChars`、`web.fetch.distillMaxTokens` |
| context | `contextPrune` 的开关与各参数、`truncationContinuation`（开关、`maxConsecutive`、`maxPerRun`）、`repetitionGuard`（开关、`mode`、`preset` 与各参数）、`memory.projectLimitChars`、`memory.userLimitChars` |
| tools | `tools.grep.maxResults`、`tools.glob.maxResults`、`tools.readFile` 的两个上限、`tools.runCommand` 的输出头尾与落盘总量、缺省与最长超时、后台作业上限与收尾时限，`sessionSearch.enabled` |
| guards & hooks | `loopGuard`（开关、`remindAt`、`warnAt`、`stopAt`）、`disableAllHooks`、`stopHookBlockCap` |
| workspace | `worktree.baseRef`、`snapshot` 的两个上限、`sandbox.memory`、`sandbox.pids`、`sandbox.cpus` |
| interface | `tui.leftArrowOpensPanel`（输入框为空时连按两下 ← 打开会话面板，缺省开着） |
| keys | 每个动作一行（Pigeon 的在前，pi-tui 部件的在后） |

不放的：结构复杂的（`mcp`、`hooks` 配置本身、`modelInfo` 的按模型覆盖、`commands` 命令短名）；权限类（`permissions`、`trustedDirectories`，`/grants` 照旧查看）；数组（`loopGuard.exemptTools`）；自由文本的地址与镜像（`web.search.*.baseUrl`、`web.search.deepseek.model`、`sandbox.image`、`sandbox.dockerfile`、`sandbox.context`、`sandbox.build.*`）。这些照旧在设置文件里写。

- 每项一行：名字、用户级写的值（`default` 即没写、取缺省）与缺省值（`default …`，暗色）；下面常显一句暗色的说明（选项名与说明；本会话设置里的生效值与用户级写的不同时附上生效值，启动参数如 `--thinking`、`--no-web` 不算在内）。被项目共享设置（`.pigeon/settings.json`）或项目个人设置（`settings.local.json`）覆盖的，名字旁标 `(overridden)`，说明里写明被哪一层覆盖与生效值（改用户级不生效）——`settings.local.json` 被 git 跟踪时按项目共享设置标。放不下时跟着选中项滚动。
- ↑/↓ 选项。开关与枚举按 Enter 或空格在可选值间轮换。数字与字符串按 Enter 就地输入：Enter 写入、Esc 取消、清空即取缺省；按范围核对（例如 `web.search.maxResults` 为 1 到 20，`repetitionGuard.similarity` 大于 0、至多 1，`sandbox.memory` 写作 `4g`、`512m` 或 `0`），非法时视图底部醒目地写原因，不写文件。
- 每改一次即写进用户级 `~/.pigeon/settings.json`（文件里的其余内容不动，`default` 即删掉这个键，路径上空了的一并删；值没变不重写，文件不存在时设成 `default` 也不新建），随后按 `/reload` 的做法重建运行面当场生效。写之前先核对整份用户级文件，再把三层合并起来核对跨字段的约束（`loopGuard` 的三个轮数须递增、`repetitionGuard` 的窗口须不小于最长重复单元乘最少重复次数、`sandbox.memory` 至少 6m 等），过不了即不写并说明——例如项目层写了 `stopAt: 20`，用户级的 `warnAt` 写 25 会被拒。视图上那一项的值当场更新就是反馈：不往消息区写，视图也不另写"已改"；改不成或重读失败时，视图底部醒目地写一句原因。
- 有几项不随重建当场生效：`web.search.backend` 换了以后 `web_search` 能不能用变了的，重启后才生效；`worktree.baseRef` 在新建工作树时才读；`sandbox.*` 在开沙箱时才读，改了之后下次开沙箱要重新确认（`sandbox` 一节按内容确认）。
- 键位组：每个动作一行，写当前生效的键与缺省键，下面一句说明；两个 Pigeon 动作绑了同一个键时两行都醒目地标出 `conflicts with …`。选中按 Enter 进入"按下新键"，下一下按键即绑定（`Shift+Tab`、`Ctrl+X` 也能绑；`Ctrl+C` 归退出，绑不了），Esc 取消，Backspace 清空（这个动作不再有键），Delete 恢复缺省。写进用户级的 `keybindings` 一节，随后重建时重装键位表。
- `/config 选项=值` 直接改一项，例如 `/config web.enabled=false`、`/config tools.grep.maxResults=500`，消息区写一行结果（如 `web.enabled = false (written to user settings)`，被别的层覆盖时同一行写明）；值没变不写文件、不重建，写一行 `<选项> is already <值>`（被别的层覆盖时同一行写明）。值不合法、用户级设置文件不是合法 JSON、是符号链接、是目录或只读时不写并说明（不把链接换成普通文件、不改权限）。读设置出错（某层文件坏了）时说明原因，视图不打开。
- 运行中或上一次改动的重建还没完时不改，说明原因、不写文件（改了也重建不了运行面）；视图照常能打开来看。视图开着时按键只归它，审批挂着时按键归审批；切到其他视图即关视图；视图开着期间排下的输入在关视图后发出。

键位可以在设置视图的键位组里改，也可以在设置的 `keybindings` 一节里写：键是动作名，值是一个键或一组键（写法同 pi，例如 `"ctrl+t"`、`["alt+up", "alt+q"]`），空数组即取消。只认用户级与项目个人层（`settings.local.json`，被 git 跟踪时不算）——仓库提交的设置改不了键位（尤其是审批键），写了的话开局在消息区提示一行；两层按动作名逐个覆盖，项目个人层优先。审批面板的提示按实际生效的键位写。未知的动作名、以及两个 Pigeon 动作绑了同一个键，开局时在消息区提示一行。

### 会话回退 `/rewind`

只在终端界面提供。空闲且输入框为空时连按两下 Esc（取消键，半秒之内），或输入 `/rewind`，打开整屏的消息列表（决策 464）：只列当前这条路上你发过的消息，每条一行（截断的文字，时间右对齐），最新的在最下面，光标缺省在最下面，`›` 标选中行；不画树线。分支用版本箭头表达：某个位置有多个版本（在它的上一条之后分了叉）时，这一行行尾显示 `‹2/2›`（正在看第几个/共几个），只在有分叉的行显示；光标在这一行时按 ←/→ 就地切换版本，下面的行随之换成那一支的消息（那一支里更深的分叉照样各自显示箭头，取这次看过的版本，没看过的取当前路径上的、都不在当前路径上取最近有动静的那个）。回退之后还没发消息时，那个位置多一个暗色的 `(no message yet)` 版本（就是现在的状态），往回切即看到原来那一支。键位：↑/↓ 选行，←/→ 切版本，Enter 打开动作菜单，Esc 关。主视图里 Ctrl+X 不绑定。运行中 Esc 照旧是中断，`/rewind` 运行中不可用。

- 选中一行回车，弹出动作菜单（标题 `Rewind to "<那条消息>"`）：`Restore code and conversation`（代码与对话都退到这条消息之前）、`Restore conversation`（只退对话）、`Restore code`（只退代码）、`Switch to this version`（只在正在看的不是当前版本时出现：整支切过去，保留它的全部对话，切到那一支的末端）、`Undo last code rewind`（只在有可撤销的上一次退代码时出现）、`Cancel`。做不到的项不出现，而不是出现了再拒。原来的后续对话不丢，留在同一会话文件里成为分支，随时可切回。
- 只能退对话时不出现两个含 code 的项（菜单下面写明原因）：这一点之后没有要退的代码；会话没有代码快照（非 git 工作区、沙箱）；这一点之后有消息没有发消息时的快照（拍摄失败或超时、在命令行里发的），分不清 agent 的改动与手改；这一点与现在不在同一个工作区（中间移进过独立工作树）——退对话后在新位置补记现在的工作树，续接时回到同一处。目标分支在独立工作树里而现在在主检出时不能切过去。退到消息之前（退了对话的）会把那条消息放回输入框，消息区按回退之后的对话重绘。
- 退代码只还原 agent 在两点之间改过的文件；以你每次发消息时在后台拍的快照为界，两条消息之间你手改、手建的文件不碰。总原则是拿不准就不写，列出来交给你：下面这些逐个列出（后面写着原因），缺省保留，空格切换为退回——agent 改过之后你又手改过的；两条消息之间被你手改过、前后又被 agent 改过的；要删的不是这段里 agent 新建的；这段里忽略规则（`.gitignore`）变过、或按现在的规则被忽略的；文件系统不分大小写时只差大小写的几个。只删在回退点确定不存在、且是 agent 在这段里新建的文件；删空的目录只删在这段时间里新建的（你原有的空目录不删；取不到目录建立时刻的系统上一律不删）。还原之前先给现状拍一份快照。快照记为过大没收的文件、被 git 忽略的文件、`.pigeon` 下的文件（不分大小写）、符号链接、有别的硬链接的文件，以及上级目录是符号链接或目录联接的路径一律不碰；没动的逐个写明原因。agent 运行期间、两次工具调用之间的手改会混进 agent 的改动，分不出来。
- 写回逐文件进行：动手之前先在会话里记下要写哪些文件，每写完一个就当场记一条（中途退出也有据可查）；每个文件写之前再核对一次（仍是普通文件、没有别的硬链接、内容没变），中途出错（只读、被占用、磁盘满等）即停，已写的与出错的照实列出，对话不退。退过代码之后，动作菜单里有 `Undo last code rewind`（撤销上次退代码），把那次写过、删过、写到一半出错的文件恢复成写回之前的样子（只退代码时同样可以）；写到一半出错的文件按出错当时记下的样子核对，之后又被改过（或当时的样子读不到）即列为拿不准、缺省保留；撤销中途出错的可以再撤；那次之后移进过独立工作树、或现在的工作区与退代码时不同（例如工作树已被清理、续接回到了主检出）的不能撤。
- 写回的内容逐字节还原：回退时把要覆盖、删掉的文件原样存下（挂在 `refs/pigeon/rewind/` 下，不被 git 回收），切回时写回原样字节。没有存下过的，取快照里的内容，按工作区当前的属性（`.gitattributes` 与 `.git/info/attributes`，只读不执行过滤驱动）判断：配了过滤器（LFS、git-crypt 等）或 `working-tree-encoding` 的、内容是 LFS 指针的、`-text` 而 `core.autocrlf` 开着的，一律列为"无法保真还原"、不写；其余按 `eol`、`text` 与 `core.autocrlf` 转换行尾，磁盘上已有的 LF 文件照 LF 写。回退点与现在之间任何一级的 `.gitattributes` 或 `.git/info/attributes` 变过时，没有存下原样字节的文件一律不写、列出。git 太旧（不支持 `--attr-source`）时没有存下原样字节的文件不写并写明。覆盖已有文件不改它的权限位；恢复被删的文件一律 0600（快照里可执行的给属主加执行位），可能比原来窄。
- 会话授权沿用回退前的状态：给过的照样有效，撤过的照样撤销（在目标分支上补记）；存进设置文件的固定授权不受影响。在跑的后台作业不停、不拦，结束通知照常送进当前对话；长期记忆不随回退撤回；会话花费按会话文件里全部分支统计；后台作业号不与旧分支上用过的重号。
- 已知的残留风险：挪主分支与补记授权在同一个写入请求里，但落盘是先后两次追加，进程恰在两次之间被杀时，撤过的授权会在续接后复活（窗口极小）。`.git/info/attributes` 里配的过滤器在拍快照时会执行（快照的既有行为）。

### 会话面板 `/panel`

一个 Pigeon 进程里可以同时开多个独立会话，各有自己的主 agent；所有会话一样（决策 484），没有特殊的"主会话"：当前窗口里显示的那个是当前会话，斜杠命令作用于它，其余的在面板里接着跑。`/panel` 打开整屏的会话面板，只列这些独立会话，按状态分组：等待回应（审批挂着）在前，其次在跑、准备中、空闲、失败、已停。每张卡写名字（`s1`、`s2`……）、派它时的那句话与摘要（最后一条回复的开头；等待回应时写在等什么，失败时写原因）。

- 工作清单（决策 485）：面板列的是一份跨工作区、跨重启的工作清单，记在用户级的 `~/.pigeon/state/session-index.json`。进过面板的会话才进清单：在面板里新开的、从主视图离开的（← ← 或 `/panel` 打开面板时的当前会话）、进入面板里别的会话时退下来的、`/resume` 换走时还在干活的；直接启动、没离开过的不进。从面板去掉即删出清单（会话记录保留）；会话文件已不在的不列。本进程没开的会话（重启前留下的、别的工作区的）卡片写 idle、摘要取会话记录里最后一条回复，不在当前会话所在项目里的在名字后标它的目录；进入即在本进程按它自己的项目与工作区续接开起来、成为当前会话；偷看取会话记录最近几句，偷看时发话先开起来再发；Ctrl+X 第一下不做事，两秒内第二下删出清单。别的 Pigeon 进程开着的标 `open elsewhere`：进入只能整屏看它的历史（发话回 `session <名字> is open elsewhere`，Esc 回面板），停不了，去掉只删本机清单里这一行。打开别的工作区的会话时用那个项目的设置；那里有没确认过的会执行命令或放权的条目（钩子、命令短名、MCP 等），在审批的位置列出（与启动时的确认同样的条目），`a` 信任（记住，同启动时的确认）、`s` 这次不用，会话照常打开，消息区留一行结论；那个项目的设置读不成（文件坏了、旧布局）或会话开不成即不开，写明原因，卡片留着。`/resume`、`/memory`、`/worktrees` 与面板里新派的会话都按当前会话所在的项目。沙箱会话没有面板，也不进清单。
- 当前会话（决策 458）：当前会话是面板的第一张卡，名字后标 `current`（暗色），状态写在卡里（等待回应、在跑、空闲），不参与按状态分组；卡上写它的首条输入与最近回复的开头。对它的操作与在主视图里一样：空格偷看它在等什么与最近几条对话，偷看时输入框里的话发给它（在跑时排队，这一轮跑完后发出）；输入框为空时回车即关面板回到主视图；连按两次 Ctrl+X 是中断它当前这一轮（不退出程序；没在跑时说明；中断途中卡上的状态写 `cancelling`）；在面板上中断时，当前会话排队的话等回到主视图时放进输入框。`/take` 它的名字时说明它的改动就在本工作区里、不用取回。
- 面板底部的输入框写一句话回车，即在当前会话所在的项目里派一个新会话去做：卡片先显示"准备中"，建工作树与开运行面在后台进行（不卡界面）。派出的会话进自己的独立工作树（`.pigeon` 下，起点按设置的 `worktree.baseRef`，缺省远端默认分支，取不到即从当前 HEAD 起并说明），开着期间持有工作树的在用锁（`/worktrees` 清理与退出清理不会删它）。
- 不是 git 仓库时（例如在主目录下启动；决策 459），派出的会话直接在当前目录里干活：不建工作树，与其他会话（含当前会话）不隔离，卡片在名字后标 `shared dir`（暗色）；`/take` 它只回一句它没有工作树（改动已经在目录里）；从面板去掉时不涉及工作树清理；会话记录里它的工作目录就是当前目录。不隔离的含义：`edit_file` 与 `write_file` 有"读后被改即拒写"的检查，不会悄悄覆盖对方的改动；`run_command` 跑的命令（脚本、格式化、构建等）不经这道检查，各自的改动合起来可能互相冲突，并行时会互相影响测试，事后也分不清是谁改的。需要隔离的，在 git 仓库里启动 Pigeon。派出的会话与当前会话一样有打转检测、后台作业结束的通知（空闲时叫醒它）、会话级钩子（SessionStart、UserPromptSubmit、SessionEnd）与 MCP；钩子与 MCP 的提示写明来源会话（出错照常醒目）；后台作业的结束通知只交给它的模型，不显示。
- 改动经 `/take <名字>` 取回当前会话的工作区（叠不上的留在工作树、会话删掉的文件不删）。完整取回之后起点前移（下次只取之后的改动；停下的会话同样）；工作树已不在时如实说明。当前会话现在就在这个会话的工作树里（取回的落点与来源是同一处）时拒绝；别的仓库里的会话不取（`<名字> is in another repository; nothing to take`）。从面板去掉时，工作树没有改动、或完整取回之后再没有改动，即删掉工作树与分支，否则保留；工作树另有会话开着即保留不删。取回（`/take` 与 `take_changes` 同一套）在 git 支持 `--attr-source` 时不走 `.gitattributes` 指派的过滤（git 按加固方式调用；行尾转换 `core.autocrlf` 照常）：用了 Git LFS 或 git-crypt 一类加密过滤的仓库，取回读写的是工作目录里的内容（LFS 的真实文件、解密后的明文），起点快照与取回起点里存的也是这样的内容，挂在本地 `refs/pigeon/` 下——不要推送 `refs/pigeon/`。子 agent 的临时工作树分支（`pigeon/...`）就是从起点快照建出来的，里面带着派出方当时未提交的改动与这样的内容：不要合并或推送这个分支，用 `take_changes` 取回；改动叠进你的工作目录之后照常由你自己 `git add`，那时过滤照常生效。`take_changes` 不写受保护的 `.pigeon/`（只列出），人用 `/take` 时照写。
- 上下键选会话；空格偷看选中的会话（等待中的问题，或最近几句人说的话与回复），偷看时输入框里的话发给它（它空闲时接着做，在跑时不收）；输入框为空时回车或 → 进入这个会话：它成为当前会话（消息区换成它的对话，历史取自它的会话记录，在跑的这一轮与排着的输入一并接过来），原来的当前会话退到面板成一张卡接着跑（在跑的这一轮、排着的输入照样带着；在面板上中断时退回的排队内容等回到它时再放进输入框）；续接、回退、重读设置、压缩进行中，或这一轮正在收尾（收尾钩子、移进工作树）时不换，回 `can't switch sessions right now`（`/resume` 同样）；面板上 Esc 关面板。
- 方向键（决策 470，照 Claude Code 的 agent view）：主视图里输入框为空时按 ←：第一下只在状态行临时显示 `press Left again to open the panel`（不写进消息区），短时间内再按一下才打开面板，并选中当前会话那张卡；中间按了别的键即撤掉第一下。输入框有字时 ← 照旧移光标；审批挂着、补全列表或查找框开着时 ← 归它们。设置 `tui.leftArrowOpensPanel: false` 关掉这个用法。沙箱会话没有面板，← 不做事。Ctrl+X（决策 483）：第一下停下选中的会话——中断它这一轮（它主 agent 挂着与排着的审批撤回），运行面不释放，它派出的子 agent（含下层）接着跑完，结果排着等它再干时一并交给它；停下的会话不被叫醒，给它发话即接着干。两秒内再按一下即从面板去掉：释放它的运行面，它派出的子 agent 一并停下；只去掉面板上这一行，会话记录保留。面板的输入框里打斜杠命令即回到主视图执行，作用于当前会话；退回排队内容的键在面板里不动当前会话排队的话。
- 任何会话及其子 agent 的审批在面板里同样显示，面板里的会话写明来源；审批挂着时，按键先归它。面板里的会话同样能派子 agent（见下文"子 agent"）；它或它的子 agent 在等审批时，卡片标等待回应（停下的会话也标，答完回到已停），当前会话那张卡同样如此。
- 面板里的会话（含停下的）不能 `/resume` 过去，也不出现在会话选择器里（先从面板去掉）。
- 关掉 Pigeon，这些会话全部停止（先等还在准备的开好，整体限时 15 秒，没停下的如实说明）；还在工作清单里的会话工作树一律留着（不删、不问），下次从面板进去接着用；当前会话不在清单里的照旧（没有改动即删，有改动问）。沙箱会话里没有会话面板。

## 子 agent

子 agent 是起点与配置不同的 agent 实例，只供模型使用（决策 457、480）：模型用 `spawn_agent` 派它干一件事，它有自己的上下文、系统提示与工具，干完把最后那段回复的全文交回派出方。终端界面的当前会话与会话面板里的会话都能派；沙箱会话与 `--no-subagents` 不提供（五件工具都不注册）。

### 五件工具

| 工具 | 做什么 |
| --- | --- |
| `spawn_agent` | 派一个子 agent。参数：`task`（要做的事；空白起步时这就是它知道的全部）、`type`（类型，缺省 `general`）、`name`（短名字，缺省按类型加序号，如 `explore-1`）、`model`（模型，缺省为类型定的，再缺省为派出方的）、`background`（缺省 true：后台跑，派出方接着干，结果以一条消息送进派出方的下一轮；false：这次调用等它干完、直接带回结果）、`inherit_context`（缺省 false；true 时带着派出方截到这一轮之前的对话起步）、`worktree`（缺省 false；true 时在临时工作树里干活，git 仓库里才有） |
| `send_message` | 按名字给本进程里的会话或子 agent 发消息：给自己派出的子 agent 追加交代、或在它干完后叫它接着干，给派出自己的那一方回话。在跑的这一轮结束后收到；已停下的子 agent 收到即接着干 |
| `list_agents` | 列出通讯录：本进程里的会话与子 agent（类型、状态、谁派的） |
| `stop_agent` | 停下自己派出的子 agent（连同它下面各层）；之后仍可用 `send_message` 叫它接着干 |
| `take_changes` | 决策 486：把自己派出的子 agent 临时工作树里自起点以来的改动（含未提交的、新建的文件）取回自己的工作目录，与 `/take` 同一套三方叠回：叠不上的留在对方工作树并列出，对方删了的这边不删、只列出；结果列出叠入、冲突与对方删了这边没删的三份清单。完整取回之后起点前移，再取只取之后的改动。参数 `name`。子 agent 取它自己派出的子 agent；会话的主 agent 另能取会话面板里同一仓库的会话（别的仓库的拒绝）。对方还在干活时拒绝。 |

`spawn_agent`、`send_message`、`list_agents`、`stop_agent` 不经审批（权限继承派出方，子 agent 自己的工具调用照常审批）；`take_changes` 会写调用方的工作目录，按写文件的规则审批（询问模式下问，放权照子 agent 的规矩只对自己有效），只读的 `explore` 不注册它。叫回停着的子 agent（发消息、后台作业结束）同样受同时在跑的上限：满了即如实说，不排队。只读的 `explore` 不注册 `spawn_agent`。名字整个进程内不重名，重名自动加序号；`send_message` 直接写名字。层数到上限的子 agent 不注册 `spawn_agent`。

### 类型

内置两种：`general`（通用：派出方的那一套工具）与 `explore`（只读探查：只给读档与联网档的工具，不能改文件、不能跑命令）。两者缺省都用派出方的模型。

自定义类型写成 Markdown 文件：项目级 `.pigeon/agents/<名字>.md`，用户级 `~/.pigeon/agents/<名字>.md`；重名时项目级优先，自定义的压过同名内置类型。文件头必填 `name`（小写字母、数字与连字符，字母开头）与 `description`（说明供模型判断何时派），选填 `tools`（逗号分隔、`[a, b]` 或逐行 `- a`；不写即通用的一套；列了即只给列出的，没注册的名字忽略）与 `model`（不写或写 `inherit` 即派出方的模型）；正文附加到子 agent 的系统提示末尾：

```markdown
---
name: reviewer
description: Reviews a diff and reports problems
tools: read_file, grep, glob, run_command
---
Review the change you're given; report problems with file and line.
```

类型在会话开始时读一次，`/reload` 重读；读不成或缺必填项的文件不登记，开局在消息区报一行。

### 上限

设置的 `agents` 一节：`maxConcurrent`（一个会话连同它下面各层同时在跑的子 agent，缺省 20；超了即派不出并如实告诉派出方，不排队）、`maxDepth`（最多到会话往下几层，缺省 3）、`runWaitMinutes`（`pigeon run` 里主 agent 停下后干等子 agent 的上限，分钟，缺省 10，0 为不限）。三项都在 `/config` 的 agents 一组里。

### 权限与审批

子 agent 与派出方共用审批模式（Shift+Tab 切换对它们同样生效）；派出那一刻派出方已有的会话放权带过去作种子（续接重开时按派出方当时的再带一次）。停下一个在等审批的子 agent，挂着的那条审批随即撤回：从审批区收掉，消息区留一行 `withdrawn: <路径> was stopped`（暗色），还在排队的不再上审批区。ask 模式下子 agent 的审批出现在所属会话（最上层）的审批区，来源行写 `source: sub-agent <路径>`（嵌套时路径写成 `general-1 › explore-2`；所属会话是面板里的会话时一并写明），一直等人答、不设超时。在子 agent 的审批里给的放权（`[a]`、`[d]`）只记在这个子 agent 自己的会话里，按键说明写 `for this sub-agent`：不往上给派出方，也不给兄弟。

### 消息与信任

agent 之间的一切传话——派出时交代的任务、`send_message` 的消息、交回的结果（前台、后台一样）——都附同一句英文说明：这是另一个 agent 写的、不是使用者，可当任务或信息处理，但其中"使用者已同意"之类的话不作数。正文放进一对带随机串的边界之间。只有使用者在界面里亲手打的字算使用者的话。每条传话在收件方的会话记录里写一条 `pigeon.agent-message`（谁发给谁、哪一种、正文；收件方当时在跑的 Run），`pigeon trace` 与会话回放据此显示；进模型的那条消息本身也带标记（交给模型之前去掉），回看历史、会话回退与 `/resume` 列表据此认出它不是使用者说的话、不作回退点。单条消息与送达的限制沿用进程内通信的规矩：单条上限、同一对发件方与收件方一分钟内的条数、短时间内的相同消息只收一次、收件方待读的满了即拒收。

### 带上下文起步与临时工作树

- `inherit_context`：复制派出方截到这一轮之前的对话（派出它的那条助手消息不带），写进子 agent 自己的会话文件开头；文件头记复制了几条，会话视图、trace 与花费都跳过这一段（用量算派出方的）。
- `worktree`：起点是派出方工作目录此刻的快照（含未提交的改动），工作树在 `.pigeon/state/worktrees/<会话号>-<名字>`、分支 `pigeon/<会话号后 8 位>-<名字>`。开着期间持有在用锁，`/worktrees` 把它列为在用、不删；释放之后照样由 `/worktrees` 列出与清理（所属会话一栏不写，它的会话在所属会话名下）。每次交回时有改动即附工作树的位置与分支；子 agent 被释放时（换会话、关掉会话或程序）没有改动即删，有改动的、干到一半被打断的保留；完整取回之后再没有改动的同样算没有改动。交回结果里附工作树时同时写明用 `take_changes` 拿回；完整取回之后再没有改动的不再附。不要合并或推送这个分支（见会话面板一节 `/take` 那段）。

### 界面

子 agent 面板在输入框下方（列当前会话的），一次只列一层：每行写名字、类型与状态（`starting`、`running`、`done`、`failed: <原因>`、`stopped`、`interrupted`、`waiting for approval`），还有下层的标 `(+N)`；钻进下层时第一行写回到会话的路径（`main › general-1`）。在跑的与已中断的一直列着，干完、失败、停下的保留约 30 秒；没有可列的行即不占地方。

- 输入框为空时按 ↓ 进入面板，↑ ↓ 选，→ 进下层，← 回上层（最上层再按即回输入框），Esc 回输入框，打别的字即回输入框照常打字。
- Enter 进入选中的子 agent 的会话：消息区换成它的对话（历史取自它的会话记录，之后实时），输入框里打的话是使用者亲手打给它的（算使用者的话，不附信任说明）：在跑时这一轮结束后收到，停着的即接着干。管整个程序的斜杠命令照用（回到主视图执行），作用于会话的回一句 `not available in a sub-agent's session`。Esc 回主视图。
- `x` 停下选中的在跑的子 agent（连同它下面各层），已结束的行按 `x` 提前清掉（只是不再列，通讯录里还在，模型照样能给它发消息）。
- 续接之后没干完的子 agent 标 `interrupted`：给它发一句话（进入它的会话打字，或由模型发消息）即从中断处接着干。
- 用 Ctrl+C 或 `/exit` 退出时还有子 agent 在跑，状态行先问 `sub-agents are still running; exit anyway? (y/n)`：`y` 或 Enter 退出，再连按两下 Ctrl+C 也算，别的键取消；审批挂着时同样先答这一句。直接关掉终端来不及问。
- 子 agent 的审批写明路径；会话面板里会话的卡片在它的子 agent 等审批时同样标为等待回应。

### 会话记录、续接与花费

子 agent 的会话存在所属会话（最上层）名下的子文件夹：所属会话的会话文件所在目录下 `<所属会话号>/subagents/`。文件头记派出方的会话号，另记名字、类型、从会话往下的路径与所属会话。它们不进 `/resume` 列表，也不进会话检索。

续接所属会话（`--continue`、`--resume`、`/resume`）时，它的子 agent 认回通讯录：最后一次没干完的（程序退出时还在跑）标为已中断，干完的为空闲；给它发一句话即重开它的会话接着干（临时工作树还在即回到那里）。程序退出（连按两下 Ctrl+C、`/exit`、直接关掉终端）时子 agent 随之停下；会话记录边干边写，最多丢进行中的那一步。

所属会话的花费（状态栏）连同它的子 agent：续接时从会话记录累计；运行中在子 agent 状态有变（派出、干完、停下）与会话自己一轮收尾时计入新增的部分。

当前会话还有子 agent 在跑时，`/reload`、`/config` 改值与 `enter_worktree` 都不做，说明 `sub-agents are running`；`/resume` 照样换，原来的当前会话带着它的子 agent 退到面板接着跑（决策 484）。闲着的当前会话被 `/resume` 换走、把面板里的会话从面板去掉时，它派出的子 agent 停下并释放；进入面板里别的会话、停下面板里的会话（Ctrl+X 第一下）时子 agent 接着跑。面板里的会话不能移进工作树（`enter_worktree` 回一句它在后台），面板派出的会话本就在自己的工作树里、不带这件工具。

### `pigeon run`

无人值守运行里主 agent 同样能派子 agent（`--no-subagents` 关掉；`--sandbox` 第一段不提供）。没有审批通道：子 agent 与主 agent 一样，要人批的调用一律拒绝。主 agent 停下时还有子 agent 在干活（在跑，或停着但它开的后台作业还没收尾），照 Claude Code 的 `-p`，运行不结束：等它们交回结果、交给主 agent 接着干，直到既没有子 agent 在干活、主 agent 也停下才结束。连续干等（从主 agent 每次停下算起）超过 `agents.runWaitMinutes`（缺省 10 分钟；0 为不限，卡住的子 agent 会一直等，要有上限就给 `--wall-clock`）即停下还在干活的子 agent、丢下它们没交回的结果，在标准错误输出写一行 `stopped <N> sub-agents after waiting <M> min`，运行照常收尾；之后主 agent 再派的照样等。撞到 `--max-turns`、`--wall-clock` 或打转叫停即照上限收尾（等子 agent 的时候撞上墙钟，终态是 `wall-clock-limit`），子 agent 一并停下。轮数只计主 agent 自己的，墙钟计入干等的时间；结果里的轮数、工具调用与用量也只计主 agent 的会话，`--json` 的保留作业连同子 agent 的一起列。

### 钩子

`SubagentStart` 在子 agent 第一轮之前触发（matcher 匹配类型名，补的上下文作任务的前缀），`SubagentStop` 在它一轮正常干完时触发（出错或被停下的不触发；拦下或补上下文即再跑一轮，连续到 `stopHookBlockCap` 后不再理会）；两者都多给 `agent_name` 与 `agent_type`，`SubagentStop` 另有 `stop_hook_active` 与 `last_assistant_message`。子 agent 不跑 `SessionStart`、`SessionEnd`；它的工具类钩子照常触发，运行记录写在它自己的会话里。

## 会话名

名字是会话自己的属性（决策 456），缺省是工作目录名加会话号末 4 位（例如 `pigeon-harness-3f2a`）。终端界面里 `/rename <名字>` 改当前会话的名字（字母、数字、下划线、连字符与点，最长 40；不收看不见的填充字符）；`/fork` 出来的分支会话不带原会话的名字，用自己的缺省名。改过的名字记进会话记录（会话文件里的会话名，不属于任何分支，会话回退不影响），退出再续接、`/resume` 换回来时都还在；还没发过消息的新会话改了名，随第一条消息一起落盘（只改名不建会话文件）。沙箱里同样能改。别处没开着的会话可以在 `/resume` 的续接视图里选中按 `Ctrl+R` 改名（规则相同；正被别的进程开着的不改）。`/resume` 的会话列表（列的是别的会话）与会话面板都显示名字；主视图不显示（决策 460），改名成功在消息区写一行 `renamed to <名字>`。名字可以重复。开局不在消息区写本会话的名字。

不提供跨窗口（跨进程）的会话间通信：原先的收件口（命名管道、Unix socket 与鉴权串）、本机会话名录、`list_peers` 工具、扣住消息的面板与设置 `messaging` 已删除（决策 457）。设置文件里还写着 `messaging` 的，开局报错，写明是哪个文件，删掉这一节即可。

## 记忆与人写的说明

学到的记忆分两层，一行一条，整份作开工状态块的「Memory」一节随第一条消息发给模型；之后每个 Run 开始与写档、命令档工具之后重读，文件变了即追加一整节取代此前的一节（模型自己用 `update_memory` 写的不再回显）：

- 项目级 `.pigeon/state/memory.md`、用户级 `~/.pigeon/state/memory.md`；文件头为英文，行形如 `- [P3] 内容 (recorded 2026-10-01 · tui · session sess_…)`（编号项目级 P 开头、用户级 U 开头；行末一段由工具补上日期、来源与会话编号，来源取入口的英文短名，现在只有终端界面的 `tui`（以前命令行对话写下的 `cli` 照旧能读）；人手加的条目可缺）。内容里的括号原样保留，只有行末最后一段算来处。删掉的编号不再分配：已分配过的最大编号记在 memory.md 旁的 `.maxid` 小文件里，新条目从记下的最大号继续。
- 旧格式（决策 431 之前：中文文件头、行末 `〔2026-10-01 · 终端界面 · 会话 sess_…〕`）的文件在第一次被读到时（开工推送、`/memory`、`update_memory`）一次性改写成新格式：先把原文件复制进迁移备份目录（项目级在 `~/.pigeon/state/migration-backup/` 下本项目的目录，用户级在其下的 `user/`，文件名 `state/memory.md`，不覆盖已有备份），再在记忆锁内整份改写——文件头换成英文，来源"终端界面"记为 `tui`、"命令行对话"记为 `cli`，认不出的来源原样，编号、内容、日期、会话编号不变；改写不另行告知，原文就在上述备份目录里。已是新格式的文件不碰。这一次拿不到锁或写不进去时，照常按转换后的新格式读出、文件不动，提示一行，下次读到时再试。
- 记使用者的偏好、纠正与代码之外的项目信息（外部资料的位置、约定、背景）；能从代码与 git 历史看出的内容不记。
- 两层各限 4,000 字符（设置的 `memory` 一节可改）。写满时新增或改长都会被拒绝：新增被拒时给出当前用量与还差多少，替换被拒时给出替换后超出多少，两种都附各条字数；改短或等长一律放行。
- 写入用 `update_memory` 工具（带 `layer` 参数，新增、按编号替换、按编号删除），写入不审批，写了什么在工具调用那一行里看得到。只有终端界面的主会话（含沙箱会话）带这个工具；`pigeon run` 只推送记忆。
- 终端界面里 `/memory` 查看两层的内容、位置与用量；`/memory edit project|user` 用 `$VISUAL`/`$EDITOR` 编辑（存盘后校验格式与上限，不合格保留原内容），改动从下一条消息起生效。保存时别的会话正在写这一层就排队等候、不设时限，等待超过 1 秒显示"正在保存记忆…（Esc 取消）"；按 Esc 取消时不保存，改过的内容留在编辑稿里。
- 启动参数 `--no-pushed-memory` 关掉推送：不推送记忆、不注册 `update_memory`，只对本次运行生效；终端界面（含 `pigeon resume`）与 `pigeon run` 接受。

人写的说明读 AGENTS.md：用户级 `~/.pigeon/AGENTS.md` 在前，项目级从仓库根到工作目录逐层拼接（某层没有 AGENTS.md 而有 CLAUDE.md 时读该层的 CLAUDE.md；不越过仓库根；不在 git 仓库里只读工作目录本身）。合计上限 32 KiB（按 UTF-8 字节），超出部分截断并在推送内容末尾与终端各提示一行。说明作开工状态块的「Project instructions」一节随第一条消息发出；之后每个 Run 开始与写档、命令档工具之后重读，内容变了即追加一整节取代此前的一节。

## 会话检索

agent 可以查本项目以前的会话，共三件工具，都是只读、免审批：

- `search_sessions`：按关键词检索以前会话。关键词大小写不敏感、按字面匹配，最多 8 个，任一命中即列出；多词的关键词拆成词分别计分，整段出现另加分；代码名整体与拆开的各段都能命中，中文按重叠二元组匹配。BM25 打分、同分从新到旧；结果按会话归并：每个会话一条，带命中条目数与一两段片段及其条目编号，缺省 5 个会话、最多 10 个。
- `read_session_entry`：按条目号读一条消息的原文（含思考内容与工具输出）。单次最多 4,000 字（`maxChars` 可调、上限 8,000），返回里给出总长度，没显示完的用 `offset` 续读；可给 `before`、`after` 连同前后各至多 5 条消息一起读（各自截断到 1,000 字）。
- `list_sessions`：列出以前的会话，每个给出会话编号、开始时间、第一句使用者的话与改动过的文件（`edit_file` 的写入与 `run_command` 报告的文件变化），可按开始时间与文件路径筛选，最多 20 个。

三件工具对不认识的参数报错说明，不静默丢弃。终端界面没有给人用的 `/search` 命令（决策 466）：想找以前的事直接问 agent；`/resume` 的会话列表打字即可按内容筛选，用的是同一套检索与缓存。

缺省范围：检索与会话目录都不含当前会话所在的这一组会话，即沿分叉关系上溯到最上层的会话，连同各级分叉（当前会话本身、续接的会话、上级与兄弟会话都在其中）；以前的工具输出（命令输出、读过的文件内容）缺省也在检索范围内，命中时片段前标出来历（工具名、关键参数、退出码或出错、时间）与"以前的工具输出，可能已过时"，只搜对话正文（使用者的话与模型回复）给 `conversationOnly: true`。这三件工具自身的输出任何时候都不进检索。

缓存：每个会话文件抽出的可搜文本、词频表与目录信息缓存在 `.pigeon/state/search-cache/`，每个会话两份（`<会话号>.json` 存目录信息与对话正文，`<会话号>.tools.json` 存工具输出），按会话文件的大小与修改时间判断是否过期，过期或损坏即重建；会话文件已不在的缓存与崩溃留下的临时文件在检索时顺手清理。可随时删除整个目录，下次检索时重建。

三件工具同进同出：终端界面与 `pigeon run` 的主会话缺省都带（本会话所在的会话树以外没有会话时三件都不注册）。使用者可以关掉会话检索（决策 382）：设置的 `sessionSearch` 一节 `enabled: false`（长期），或启动参数 `--no-session-search`（只对本次运行生效；终端界面（含 `pigeon resume`）与 `pigeon run` 接受）；关掉即三件都不注册，开局记录写明原因。使用者在终端界面里用 `/search <关键词…> [--conversation-only] [--role user|assistant|toolResult] [--limit N]` 检索，走同一套检索与缓存（任一命中即列出、BM25 打分、按会话归并），加 `--conversation-only` 只搜对话正文；人用的 `/search` 不排除当前会话；命中以前的工具输出时照样列出（以前的工具输出可能已过时）。

## 迁移命令

```
pigeon migrate-config [--root <项目根>]
```

- 7 个旧配置文件各成一节写入设置：`permissions` 写项目个人 `.pigeon/settings.local.json`，其余写项目共享 `.pigeon/settings.json`；处理过的旧文件一律挪出仓库，原名放进用户级 `~/.pigeon/state/migration-backup/<项目目录名>-<哈希>/`（按项目的规范化路径分目录），迁移结束打印这个位置；仓库里不留备份（旧 `web.json` 里可能有 key，留在仓库里会进快照、沙箱容器与工作树，也可能被提交）。除 `web.json` 外备份即原文。
- 每次迁移都确保程序状态与个人设置的忽略规则在全局 git 排除文件里（见上文"程序状态目录"），不再写 `.pigeon/.gitignore`。
- `web.json` 里的 key 不写入设置，打印应设的环境变量名；备份里字段照留，key 的值换成"已移除，请改设环境变量 …"。key 不出现在任何输出与备份里，`web.json` 不是合法 JSON 时报错也不带解析细节。迁移会去掉旧 `web.json` 里 key 的原文、不保留任何副本，也不因环境变量没设而拦住；迁移前先把 key 设进对应的环境变量或另行保存。更早的迁移留下的备份不改动，其中可能仍有 key。
- `.pigeon/verify.json` 不并入设置：验证门已随决策 322 退役，迁移把它挪进备份目录，并打印把原验证命令改写为收尾（Stop）钩子的配置示例（分步配置按各步命令以 `&&` 连接）。
- 旧位置的程序状态移入 `.pigeon/state/`；旧位置的工作树用 `git worktree move` 移动。
- 已删除功能的遗留挪出仓库进用户级备份目录：旧学到的记忆（`.pigeon/learned/`、`.pigeon/state/learned/` 与它们的锁）、补做复盘记录（`.pigeon/review-backfill`、`.pigeon/state/review-backfill`）、复盘配置 `.pigeon/memory-review.json`、旧人写说明 `.pigeon/memory/`（另打印提示"把其中内容并入项目的 AGENTS.md"）。
- 用户级旧偏好 `~/.pigeon/preferences.md` 改名为 `~/.pigeon/AGENTS.md`；目标已存在即拦阻、不覆盖。
- 目标设置文件已存在时合并进去；同一节两边都有且内容不同则报错停下，不覆盖。
- 有 Pigeon 会话正在运行（锁被占用）、或工作树被锁定时拒绝并说明。
- 可重复执行；没有要迁移的内容时如实说明。

启动时（终端界面、`pigeon resume`、`pigeon run`）发现任一旧配置文件、旧位置的状态或已删除功能的遗留（复盘配置与补做记录、旧学到的记忆、`.pigeon/memory/`、`~/.pigeon/preferences.md`）即报错，提示运行 `pigeon migrate-config`，不自动迁移。

## 会话中途重读设置：`/reload`

终端界面里输入 `/reload` 重读三层设置，形成新快照：

- 执行命令类配置（命令短名、沙箱配置连同 Dockerfile、MCP 启动定义、钩子）与项目共享层的放行规则有变化（含首次出现）且未经确认的条目，照启动时的确认流程列出；`/reload confirm` 全部确认（记下指纹）并生效，`/reload skip` 不确认，这些条目沿用原内容，原来没有的不启用。新快照里的钩子自 `/reload` 起按新快照生效（终端界面在拦下或出错时的提示、`/hooks` 的清单随之更新）。
- 新快照自下一轮起生效：放权、命令短名等此后即按新快照；运行面按新快照重建，结果行列出改了哪些节与重启、停止、启动的服务。
- MCP 服务只动有变化的：启动定义改了的重启，删掉的停止，新加的启动；启动定义未变的沿用原连接、不重启（只改风险档也不重启），服务自己的状态（例如浏览器类服务的登录与页面）得以保留。
- 系统提示在 `/reload` 后逐字节不变（续跑时所用模型变了才按新模型重建，决策 430）；按环境注册的工具（含有无 `load_skill`）沿用开局的判断。人写的说明（AGENTS.md）、推送的两层记忆、Skill 目录不靠 `/reload`：它们在开工状态块里，每个 Run 开始与写档、命令档工具之后重读，变了即整节追加。由设置决定的部分（联网工具与 MCP 工具的增减，审批、联网、外部工具几节的说法）按新快照变，状态块里变了的节同样整节追加。
- 正在跑的沙箱容器不重建：在沙箱会话里 `/reload` 且 `sandbox` 一节有变化时，提示退出后用 `pigeon --sandbox --resume <会话号>` 续跑才对本会话的容器生效。
- 主 agent 正在运行时不重读。
- `pigeon run` 不设重载。

## 读档工具：图片与二进制文件

`read_file` 按文件头（不看扩展名）认出 PNG、JPEG、GIF、WebP 四种图片，并从文件头读出像素尺寸（决策 414）。模型能看图（模型信息的输入类型含 `image`，见上文"模型信息"）且图片在单张上限以内时，结果是一行"路径、类型、像素尺寸、字节数"加图片本身；工具说明随之写明可读图片。单张上限：长边不超过 2000 像素、base64 编码后不超过 5 MB（5,000,000 字节；常见服务方单张上限中较严的一档；一条请求里图片较多时，有的服务方会把单边上限降到 2000 像素）。超出单张上限的图片先在 Pigeon 进程里缩小再交出（决策 416，用 WebAssembly 编译的图像库 photon，四种格式都能处理）：长边超过 2000 像素的等比缩到 2000，尽量保持原格式（PNG、WebP 照原格式，JPEG 质量 85，GIF 取第一帧转 PNG）；缩后仍超字节上限，或只是字节超限，转 JPEG 并按质量 85、70、55、40 逐级降。结果那一行写明交出的格式、尺寸与字节数，以及图中坐标换算回原图要乘的倍数。在限内的图也先完整解码一遍再交出（决策 417）：截断或损坏、解不开的图交出去会让服务方拒收整条请求，且它留在历史里之后每次请求都会被拒，所以只给元信息。图像库载入失败（此时无法核验）、图片解不开或降到最低质量仍超限时，都退回只给元信息。缩放不处理 EXIF 方向，转 JPEG 时不保留透明。读不出尺寸的（文件头不完整或损坏）只给元信息并说明原因。模型不能看图时图片只给元信息，并提示可用命令行工具处理。

打包产物里，photon 的 wasm 文件（`dist/photon_rs_bg.wasm`）随产物一起放在 `dist/` 下；只放 `dist/` 的部署照常可用，缺了这个文件即按载入失败处理。

MCP 工具返回的图片在模型能看图时走同一道关口（决策 417）：按文件头认类型与尺寸（不信声明的类型）、完整解码一遍、超出单张上限的缩小；不过关的图片块换成一行"[图片未交出：原因（类型 宽×高，字节数）]"，缩过的在图片前加一行说明，文字块不动。

请求仍被服务方拒收时（决策 417）：模型请求以 HTTP 400 出错（按错误文本开头的状态码判断，不看服务方的报错文案），且这次请求里有上次成功回复之后新加的带图工具结果，就把这些结果换成占位——原有文字照留，图片换成一行"图片未被服务方接受：读的是哪张图、类型与尺寸"——再重试一次；仍失败按原错误收尾。占位走上下文裁剪的记录（时机 `rejected`、原因 `rejected`），先写进会话记录再生效，续跑、分叉与压缩后的还原都照记录重放，图不会回来；出错的那条回复照实留在会话记录里，不再发给模型。一个 Run 只重试一次；只换新加的图，之前已被接受的图照发；思考块等其余内容不动。这项处理不受 `contextPrune.enabled` 约束。

不是这四种图片的文件，满足任一条即按二进制处理：开头 8000 字节里有 NUL（与 Git 判二进制同一口径，UTF-16/32 编码的文本也在此列）；文件头是认得的二进制格式（PDF、ZIP、gzip、xz、7z、ELF、SQLite、WebAssembly、TIFF）；开头 8000 字节里非法 UTF-8 序列的个数超过字节数的一成（其他编码的文本，或没有 NUL 的二进制）。二进制文件只给类型（认得的格式）与字节数，并提示可用的命令行工具（`file`、`xxd`、`strings`；其他编码的文本可用 `iconv` 转成 UTF-8），不再把解码出的乱码放进上下文。少量非法字节（个别 Latin-1 重音字母等）不妨碍阅读，仍按文本读。

图片与二进制文件整个交回、不分行，`offset`、`limit` 不适用，结果不带快照与行锚点。这类读取与文本读取一样记进读取记录：之后用 `write_file` 覆盖须读后未变。文本文件的行为（分页、行号、锚点、字节与单行上限）不变。会话记录里图片按原样保存；回看历史、`pigeon trace`、`pigeon replay` 带正文时，工具结果照常折叠，注明图片张数，不显示图片内容。

## 读档工具：工作区外只读

`read_file` 可以只读工作区以外的文件（决策 355）：`--yolo` 下自动放行；不开放手模式时须经人批准，审批面板标明"工作区以外（只读）"与解析后的真实路径，可批准一次、按所在目录放权或按工具放权；没有审批通道（`pigeon run` 等无人值守运行）时拒绝——但设置里固化的 `read_file` 放权（`permissions.grants`，按工具或按目录）照样放行，它就是人事先给的批准，与写档的放权同一口径。沙箱会话按容器里的路径判定。

`write_file` 与 `edit_file`（两种编辑模式）在放手模式下（`--yolo`，以及沙箱缺省的放手审批档）接受工作区以外的路径（决策 407），例如系统临时目录、`/etc`、`/usr/local` 下的文件，与放手模式下命令能写任何位置一致；工具说明随之写明可用绝对路径写工作区以外。其余规矩照旧：要写的文件本身是符号链接拒写、不写版本库元数据（`.git`）、覆盖已存在的文件前须读过、写入前重新解析复核。不开放手模式（交互逐条询问、`pigeon run` 等无人值守又未放手）时照旧只写工作区，越出即报"路径越出工作区根"。写到工作区以外的文件不计入工作区的改动（后台作业期间的前台改动不记它们）；

工作区内外按符号链接解析后的真实路径判定（本机用系统的 realpath：Windows 上 8.3 短名、大小写与 `\\?\` 前缀都归一到同一写法；Windows 与 macOS 上不分大小写比较），经工作区里的链接指到工作区以外的同样算工作区以外。家目录里的凭据目录（如 `~/.ssh`、`~/.aws`）不另设限制，与其他工作区以外的文件同一规则（决策 412）；Windows 上设备前缀（`\\?\`、`\\.\`）、数据流（`name:stream`、`::$DATA`）与 UNC（`\\server\share`）的写法也照解析后的真实路径判定，UNC 写法即使指向本机上工作区里的文件（如 `\\localhost\C$\…`），只要工作区不是以同一写法打开的，也按工作区以外处理。设置里旧有的 `permissions.readDeny`（原先禁读名单的追加项）照常加载、不报错，已不生效。

`grep`、`glob` 只搜工作区之内：`path` 落在工作区以外即拒；结果逐个文件按真实路径过滤，经符号链接指向工作区以外的滤掉，文件名含换行或控制字符的文件一律略去，末尾注明各类略去的文件数；一次最多检查 20,000 个文件，超出或检查超时的略去并注明结果不完整。

`grep`、`glob` 两个读档工具（决策 368）经执行端在本机或容器里运行：优先 ripgrep（本机随包附带，依赖 `@vscode/ripgrep`，按平台拆成可选依赖、二进制直接打在包里，MIT），没有则在 git 仓库里用 `git grep`、`git ls-files`，再退到 `grep -r`、`find`。这些后端是 Pigeon 自己的辅助程序，不走 agent 的执行通道：程序先解析成绝对路径再启动（本机在 PATH 的绝对目录里找，跳过相对目录与工作区之内的目录，ripgrep 只用随包二进制；容器里系统目录优先），输出一律无歧义（rg 用 `--json`，git 用 `-z` 并把文件名含控制字符的文件排除在搜索之外，`grep -r` 降级先列出候选文件、按真实路径筛过再逐个搜，搜时先打开文件、按 `/proc` 给出的已打开文件的真实路径复核，没有 `/proc` 时不复核），git 不读系统与全局配置并关掉 `core.fsmonitor`，ripgrep 不读配置文件（`RIPGREP_CONFIG_PATH`）、`.ignore` 与全局 gitignore。缺省遵守 `.gitignore`（只在 git 仓库里）、跳过 `.git`；结果条数上限见 `tools` 一节。

`grep` 的内容结果按文件分组（决策 408）：每个文件先写一行路径，其下逐行"行号: 内容"（上下文行为"行号- 内容"，同一文件里不相连的段之间用 `--`），文件之间空一行；`files_only` 的输出不变，每行一个路径。列出的部分另设 16,000 字的预算（常量）：超出时结果里只放前面放得下的整行，末尾写明总匹配条数与文件数，提示宽泛的搜索先用 `files_only` 只列文件或缩小 `path`；条数上限以内的全文存进会话的落盘目录，给出虚拟路径 `pigeon://outputs/<会话号>/<编号>`，与 run_command 的完整输出同一处、同样用 read_file 读，计入同一落盘总量上限（`tools.runCommand.savedOutputsMaxBytes`）。

## 本机模式的风险与容器沙箱

本机模式（不加 `--sandbox`）下没有系统级隔离（决策 378、379）：

- 命令以你的账户直接执行，能读写你的账户能读写的文件，包括家目录里的凭据；网络出站不受限。放手模式（`--yolo`）下这些命令不经审批，等于把你的账户交给模型。启动时不另行提示（决策 460），风险以本节为准。
- 改文件工具上的路径检查（受保护路径、工作区边界，写入时重新解析复核）是防失手，不是安全边界：检查与写入之间仍有极短空档，命令也能直接写这些位置。放手模式下改文件工具不查工作区边界（决策 407）。要硬隔离用容器沙箱档。
- 不信任的仓库，或开着联网工具时，用容器沙箱档 `--sandbox`。容器档缺省联网、缺省放手（`--sandbox-approval prompt` 改回逐条询问）；要防工作区代码经网络外泄，加 `--sandbox-network off` 断网，联网工具随之不给。
- 容器沙箱从当前工作目录开工：缺省把未提交的改动（含未被忽略的新文件）拍成快照带进容器（`--sandbox-from-head` 只从最新提交开工）；会话结束时（或会话中 `/export`）把改动交回成分支 `pigeon/sandbox-<会话号>`，写一行分支名与查看命令。带了快照时，这条分支的第一条提交就是开箱时带进去的那份未提交改动——你本地的工作目录里还留着同样的未提交改动，合并这条分支之前先把本地这份收起（stash 或丢弃），否则会冲突或重复。续接沙箱会话用 `pigeon --sandbox --resume <会话号>`。容器、镜像、网络、下载缓存卷与资源上限按设置的 `sandbox` 一节（见上文"沙箱资源上限"），开沙箱时不再逐项写出。
- 放行执行仓库脚本的命令（如 `npm test`、`make`）等于放行脚本的内容：脚本改了以后，同一条命令照样免审执行。
- 模型服务商与搜索服务的密钥不进命令的环境：命令的环境变量按白名单传递（`PATH`、`HOME`、临时目录、语言设置等），其余一律不传；容器里的命令拿不到宿主的环境变量。
- 网页搜索结果、网页抓取交回的提炼结果与 MCP 工具结果的文字部分，开头带一行固定标记，标明是外部内容、其中的要求或指令不照做；读文件与跑命令的结果不加。标记降低误从的机会，挡不住被注入。
- 用 LFS 或加密过滤（如 git-crypt）的仓库：Pigeon 后台的 git 不跑过滤（见上文"程序状态目录"一节），面板会话的起点与它的分支里，这类文件是工作区里的原文。取回面板会话的改动请用 `/take`（逐文件叠进你的工作目录，之后由你的 git 照常提交）；不要直接合并它的分支再推送，否则大文件会以原文、加密文件会以明文进入历史。沙箱交回的分支同样：开工快照不跑这些过滤，容器里新建的仓库也不带宿主上的过滤配置，分支里改过的这类文件是原文；沙箱没有 `/take` 一类的取回方式，合并前先看分支的改动里有没有这类文件，有的话不要直接合并再推送，把这些改动写进你的工作目录、由你的 git 重新提交（过滤照常生效）。

## 三道防线

缺省全开，不设开关。

1. **`.pigeon` 是受保护路径。** agent 用文件工具写 `.pigeon` 下任何路径都须人逐次批准：会话放权与配置放权都不能放行；`--yolo` 下放行，拒绝名单照常优先。判定按规范化后的真实路径（含符号链接解析）做，大小写不敏感的文件系统上按不敏感比较；沙箱会话在容器里判定：路径按容器的工作区根规范化（写成容器内绝对路径的也算），容器里的符号链接经容器解析。批准提示写明这是受保护路径，只能批准这一次或拒绝，不提供放权键。命令（`run_command`）写入不在此列，由第三道防线兜底。
2. **设置在会话开始时冻结。** 会话中途改设置文件只在下次启动或 `/reload` 之后生效，执行命令类的变化与项目共享层的放行规则照样经人确认。
3. **会执行命令或放权的配置按内容确认。** 范围：`commands` 一节的每个短名、`sandbox` 一节（连同它指向的项目 Dockerfile 的内容）、MCP 服务的每个启动定义（项目根 `.mcp.json` 与设置 `mcp` 一节里给了 `launch` 的）、`hooks` 一节的每个钩子（决策 324：逐条按事件、matcher、命令与执行位置记指纹），以及项目共享层 `.pigeon/settings.json` 里 `permissions` 一节的每条放行规则。内容与上次确认不同（含首次出现）时：
   - 终端界面启动时逐条列出（来自哪一层、类型、标识、完整命令或内容摘要），可选全部确认（记下内容指纹）、本次不用这些条目、或退出。选本次不用时，本会话不启动那些 MCP 服务、不展开那些短名、沙箱不用该配置、那些放行规则不生效（相应的操作照常请示）。
   - 放行规则逐条确认：每条规则按整条内容（规范化 JSON 的 sha256）记指纹，列出时标识为指纹前 12 位、内容为整条规则；规则内容一变即是新的一条，须重新确认；同样内容的多条只确认一次。克隆来的仓库可能自带放行规则，例如一条 `tool` 为 `run_command`、`shell` 为 `true` 而不写具体命令的规则即放行全部命令，确认前它不生效。用户级与项目个人层 `settings.local.json` 的放权由使用者自己写入，直接生效、不需确认。
   - 钩子逐条确认：每个钩子按事件、matcher、命令、超时与执行位置记指纹（决策 324）；内容一变即是新的一条，须重新确认；三层给出的钩子都算。
   - `pigeon run` 开跑前报错退出并逐条列出；加 `--trust-config` 只对本次运行放行，不记指纹。
   - 项目位于用户级设置 `trustedDirectories` 中任一目录之下时免于本道确认；项目级设置写这个键即报错（项目不能为自己免检），相对路径也报错。

## 钩子

钩子是在会话的各个时刻自动执行的命令（决策 323 / 324）。一切照 Claude Code 的协议做，工具名用 Pigeon 自己的。

### 配置结构

`hooks` 一节：事件名 → matcher 组数组；每组有一个可选 `matcher` 与一个 `hooks` 数组；每个钩子只支持 `type: "command"`（保留 `type` 字段以便以后扩展）：

```json
{
  "hooks": {
    "Stop": [
      {
        "hooks": [{ "type": "command", "command": "npm test 1>&2 || exit 2", "timeout": 600 }]
      }
    ],
    "PreToolUse": [
      {
        "matcher": "run_command",
        "hooks": [{ "type": "command", "command": "node check-danger.mjs" }]
      }
    ]
  },
  "disableAllHooks": false,
  "stopHookBlockCap": 8
}
```

- `matcher`：工具类事件按正则匹配 Pigeon 的工具名（非锚定；`Edit` 也命中 `Edit|Write` 这类写法请写成 `^edit_file$` 这样的显式正则）；其余事件匹配各自的取值（`SessionStart` 的 `source`、`SessionEnd` 的 `reason`、`PreCompact`/`PostCompact` 的 `trigger`、`Notification` 的通知种类）。缺省、`*` 与空串匹配全部。非法正则在校验时报错。
- `timeout`：秒。缺省：`UserPromptSubmit` 30 秒、`SessionEnd` 1.5 秒（单个钩子可提高，最长 60 秒）、其余 600 秒。
- `host`：可选布尔；`true` 表示这个钩子在宿主执行（沙箱会话里其余钩子在容器里执行）。
- 三层合并：各层的条目并列生效（不去重事件或 matcher）；同一事件同一 `matcher` 下命令完全相同的只执行一次。
- `disableAllHooks`：顶层键，停用全部钩子（三层按标量覆盖，高优先层说了算）。启动参数 `--no-hooks` 只对本次运行停用全部钩子。
- `stopHookBlockCap`：收尾钩子连续拦截上限，缺省 8。
- 钩子在会话开始时随设置快照冻结；每个钩子逐条接入执行命令类配置的内容确认（第三道防线），内容一变须重新确认。

### 事件

首批 13 个（决策 323）：

| 事件 | 何时触发 | 能做什么 |
| --- | --- | --- |
| `SessionStart` | 会话开始或续跑时 | 补上下文（以一条上下文消息进入，不改开局冻结的系统提示；随下一条输入一起交给模型，只带一次） |
| `SessionEnd` | 会话结束（退出、换绑、`pigeon run` 结束） | 只作副作用 |
| `UserPromptSubmit` | 使用者的输入交给模型之前 | 拦下、补上下文；不能改写 |
| `PreToolUse` | 工具调用之前、审批之前 | 拒绝、要人确认、放行、改参数、补上下文 |
| `PostToolUse` | 工具调用成功之后（后台运行的 run_command 在启动时） | 替换工具结果、把理由交给模型、补上下文 |
| `PostToolUseFailure` | 工具调用失败之后 | 把理由交给模型、补上下文 |
| `Stop` | 一轮回复收尾 | 拦住要求接着干、补上下文 |
| `StopFailure` | 一轮以出错结束 | 只作副作用 |
| `SubagentStart` | 子 agent 第一轮之前（matcher 匹配类型名） | 补上下文（作任务的前缀） |
| `SubagentStop` | 子 agent 每次停下（matcher 匹配类型名） | 拦住要求接着干、补上下文 |
| `PreCompact` | 上下文压缩之前 | 只通知，不能拦（拦下压缩会让下一次请求超长出错） |
| `PostCompact` | 压缩完成之后 | 只作副作用 |
| `Notification` | 需要使用者注意时：终端界面审批面板出现（`notification_type` 为 `permission_prompt`）；`message` 为面板提示原文 | 只作副作用 |

`PreToolUse` 的结论合并：拒绝 > 要人确认 > 放行。**放行只免掉人工审批这一步**——拒绝名单、路径围栏与受保护路径照常生效；改过的参数重新经过全部检查。`Stop`/`SubagentStop` 连续拦截到上限（`stopHookBlockCap`）后不再理会、照常结束，结束原因记为"收尾钩子拦截到上限"（不贴失败标签）。

### 协议

事件信息以 JSON 经标准输入交给命令（公共字段：`session_id`、`cwd`、`hook_event_name`、`permission_mode`（本会话的审批档：`yolo` 或 `prompt`）；各事件自己的字段如 `tool_name`/`tool_input`/`tool_use_id`、`prompt`、`source`、`trigger`、`stop_hook_active`、`last_assistant_message`、`error`、`message` 等照 Claude Code）。环境变量 `PIGEON_PROJECT_DIR` 指向项目根。

退出码：`0` 放行；`2` 拦下（标准错误为理由）；其他为钩子自身出错，不拦只提示。标准输出可以是一个 JSON 对象：

```json
{ "continue": false, "stopReason": "停下", "systemMessage": "注意",
  "decision": "block", "reason": "理由",
  "hookSpecificOutput": { "hookEventName": "PreToolUse", "permissionDecision": "deny",
    "permissionDecisionReason": "理由", "updatedInput": { "…": "改后的参数" },
    "additionalContext": "补的上下文", "updatedToolOutput": "替换后的工具结果" } }
```

`continue: false` 结束本轮处理：`PreToolUse` 给出时，本批其余调用一律拦下（不再执行它们的钩子、不再请示）；`PostToolUse`/`PostToolUseFailure` 给出时，同批里尚未准备的调用一律拦下，而并行批次里已经准备好（`PreToolUse` 与审批已过）的调用仍会执行完，只是不再跑它们的收尾钩子（各环境里纯读的一批并行执行：`read_file`、会话检索三件、`web_search`、`web_fetch`、`job_output`；一批里有别的工具即整批逐个执行）。两种情形下这批工具之后都不再问模型，本轮以中止收尾、原因记"钩子要求停止：<stopReason>"，也不再触发 `Stop`；`Stop` 拦下后续跑的那一轮以出错或中止收尾时，不再触发 `Stop`、终态如实记。

同一事件命中多个钩子时并行执行；每个钩子的运行写入会话记录（事件、命令、退出码、用时、结论、输出摘要），`pigeon trace` 与会话回放显示：Run 之内的挂在该 Run 下，Run 之外的收尾类（`Stop`、`StopFailure`、`SubagentStop`、自动压缩的 `PostCompact`）挂刚结束的 Run，其余（`SessionStart`、下一条消息的 `UserPromptSubmit`、手动压缩、`Notification`、`SessionEnd` 等）为会话级条目；终端界面在拦下、要求停止或出错时显示一行（醒目，只这一行，不再重复），`/hooks` 列出生效的钩子及其来自哪一层。

### 执行位置

钩子在工作区所在处执行：本机会话在本机、沙箱会话在容器里（经执行端）；`host: true` 的单个钩子指定在宿主执行。超时或取消时杀掉整棵进程树（非 Windows 用独立进程组、Windows 用 `taskkill /T /F`）。容器里的钩子以容器内的 `timeout` 限时，到时只终止该钩子、不重启容器（`timeout` 不认 `-k` 时用不带 `-k` 的写法；镜像里没有 `timeout` 时退回断开并重启容器）。

代价：钩子没有常驻进程，每命中一次起一个新进程（经 shell 时还要多起一个 shell），等它退出才继续；沙箱会话里每次另加一次进容器。`PreToolUse`、`PostToolUse` 按工具调用逐次触发，matcher 写得越宽，每轮多出的进程越多：只给真正要拦或要记的工具配钩子，耗时长的检查放进 `Stop`（每次运行收尾时触发一次）。

### 示例

收尾时跑测试（原验证门的替代）。拦下靠退出码 2 与 stderr：命令失败时把输出导到 stderr 并以 2 退出（`1>&2 || exit 2`），否则失败的输出落在 stdout、退出码非 2，拦不住：

```json
{
  "hooks": {
    "Stop": [
      { "hooks": [{ "type": "command", "command": "npm test 1>&2 || exit 2" }] }
    ]
  }
}
```

拦危险命令：

```json
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "run_command",
        "hooks": [{ "type": "command", "command": "node .pigeon/hooks/deny-danger.mjs" }]
      }
    ]
  }
}
```

`deny-danger.mjs` 从标准输入读事件 JSON，命中危险命令时以退出码 2 结束并把理由写到标准错误：

```js
let data = "";
process.stdin.on("data", (chunk) => (data += chunk));
process.stdin.on("end", () => {
  const input = JSON.parse(data);
  const command = String(input.tool_input?.command ?? "");
  if (/\brm\s+-rf\b/.test(command)) {
    process.stderr.write("禁用 rm -rf：请改用可审计的删除方式");
    process.exit(2);
  }
  process.exit(0);
});
```

钩子执行项目代码（脚本、测试），这些代码 agent 可以改；需要隔离时用沙箱会话。
